## 1. 业务需求（译文 §6 摘编）

以下内容完整摘编自译文 §6「简体中文本地化」。原文 §6 本身**无批注**（Michael Zhang 的 4 条批注均锚定在 §4.3/§5.3/§7.2/§7.4，与本模块无直接关联）；但执行摘要（§1）与 §6 存在**范围不一致**，见本节末尾说明。

### 1.1 需求（§6.1）

- 必须新增简体中文为系统支持语言；
- 对于 Ocean Island 的餐厅客户，简体中文应可作为**主要订购语言**；
- 系统必须继续支持英语作为回退（Fallback）语言。

### 1.2 语言行为（§6.2）

系统应支持：

- 英语；
- 简体中文；
- 语言选择器；
- 按实体或按用户的默认语言设置；
- 为指定的 Ocean Island 用户将中文设为默认语言；
- 翻译缺失时回退到英语。

### 1.3 翻译范围（§6.3）

首期中文翻译应覆盖**完整的订购工作流**，包括：

登录与认证、导航菜单、产品分类、产品目录页、产品详情、搜索与筛选、购物车、订单确认（下单前核对）、订单提交、订单确认（提交成功）、订单历史、订单状态、通知、校验提示信息、错误信息、**执照状态与到期提示信息**、价格与单位标签。

> 供应商录入的信息（如产品名称、产品描述、品牌、自定义分类）应**按供应商录入时的语言展示**，除非另行提供了翻译内容。

### 1.4 翻译管理（§6.4）

- 用户界面翻译应存放在**集中式的本地化文件**中，而不是硬编码在各个页面里；
- 系统应支持在不做大规模应用改动的前提下，对翻译进行后续修正或扩充。

### 1.5 验收标准（§6.5，原文）

- 用户可以在语言选择器中选择简体中文；
- Ocean Island 可以为指定用户将简体中文设为默认语言；
- 餐厅端完整订购流程均有简体中文；
- 英语仍然可用；
- 缺失的中文翻译回退到英语，不出现空白标签或系统错误；
- 货币、日期、数量和单位在两种语言下均正确显示。

### 1.6 其它章节相关条款

| 条款 | 内容 |
|------|------|

### 3.2 可测试化补充

| # | 验收项 | 可测试描述 |
|---|--------|-----------|
| AC-1 | 语言选择器可选中文 | 登录任意账号 → Settings → General Settings → Language 下拉出现「English / 简体中文」两项；选择「简体中文」并保存后，整站界面立即切换为中文，**无需刷新**；刷新页面后仍为中文（localStorage `i18nextLng` 持久化） |

| AC-3 | 订购全流程中文 | 以餐厅账号用中文完成一次完整下单：登录 → 导航 → 目录浏览（含分类/筛选/搜索）→ 产品详情 → 加入订单 → 核对订单 → 提交 → 提交成功确认 → 订单历史/状态查看。全流程**不出现英文界面文案**（供应商录入的产品名/描述等业务数据除外，按 §6.3 规则展示） |
| AC-4 | 英语可用 | 切回 English 后所有页面回到英文，无残留中文界面文案 |
| AC-5 | 回退不空白 | 人为删除 zh 某 namespace 的任意 key 后，对应 UI 位置显示英文原文，**不显示 key 名、空白或报错**；zh 文件整体缺失时页面完整回退英文且无控制台错误导致的白屏 |
| AC-6 | 格式正确 | 中文语言下：金额仍以 USD 计价且格式合法（如 `US$1,234.56`）；日期按 zh 习惯格式显示（如 `2026/07/20` 或 `2026年7月20日`，实现取其一并全站一致）；数量、单位标签中文化。英文语言下维持现有 `$1,234.56` / `MM/dd/yyyy` 不回归 |
| AC-7 | 双语品名 | 中文界面下产品优先显示 `name_zh`，缺失回退 `name_en`；英文界面反之（依 Q11 建议方案，待确认） |
| AC-8 | 手动退出不改语言 | 退出登录/会话过期跳转登录页时，界面保持当前语言不重置 |
| AC-9 | 键一致性 | CI 中的 locale key 一致性检查通过：`zh/*.json` 与 `en/*.json` 键集合逐 namespace 对齐（允许 zh 暂缺、报告缺失清单；不允许 zh 出现 en 没有的孤儿 key） |
