## 1. 方案概述

**数据模型**：新增 `price_tier` 表（store/vendor 维度，照抄 `payment_method` 字典表范式：name 唯一、created_by、删除受限 409），等级集合是 vendor 级统一维度（Q2-A）。定价不另建价格表，而是给现有 append-only 的 `product_price` 表加 `tier_id` 维度（`NULL` = 基础价，向后兼容存量行），改价 = 追加新行、当前价 = 该 `(product_id, tier_id)` 最新一行——append-only 语义天然满足 §7.8 定价审计要求，只需补 `changed_by_user_id` / `import_job_id` 两列。三态可购性由独立表 `store_product_tier_availability` 承载（缺行 + 缺价 = 「未配置价格」态）。客户分配为 `client.price_tier_id` 单值外键（`ON DELETE RESTRICT` 兜底防误删）。

**读写路径**：管理侧新建 `core/price_tiers/` 领域五件套 + `main_app/vendor/price_tiers/` 传输层，提供等级 CRUD、客户分配（单个/批量）、产品×等级定价矩阵（产品维度与等级维度双入口，回应批注 3/Q3）。客户侧改造现有读价链路：产品列表/详情按请求方所属 `client.price_tier_id` 取价，缺价返回 `PRICE_NOT_CONFIGURED`（前端展示「请联系供应商询价」），**绝不回退基础价或他 tier 价**（§7.6/Q1-A）；两条下单链路（餐厅端 `POST /restaurants/{restaurant_id}/orders`、供应商代下 `POST /vendors/{vendor_id}/orders`）落 `OrderProduct.price` 快照时取价源改为客户 tier 当前价，快照与 `order_product_price_history` 机制不动，历史订单/发票天然锁价。

**导入**：新建 `store_import_job`（kind = `CLIENT` / `TIER_PRICE`），仿厂商域 `manufacturer_catalog_import_job` 的 **prepare→commit 两阶段**（幂等、重复提交 409、逐行错误报告），全流程 upload → 列映射 → 校验 → commit；不学旧 OCR webhook 直写业务表。客户导入承载 §7.7 五列（含执照两列透传给执照模块）。

**风险控制**：`StoreProduct.price` column_property（`core/products/models.py:191-200`）当前取「最新一条」，`product_price` 加 tier 维度后**必须补 `tier_id IS NULL` 过滤**，否则基础价静默取到 tier 价——列为代码评审必查项。`_build_calc_input`（`core/orders/services.py:379`）是发票/月结/报表共同上游，其「回退 `product.price` 基础价」分支在 tier 场景是错价风险，改造必须带全量订单-发票回归测试。

## 2. 表结构设计

以下 DDL 逐字摘自[《开发方案-表结构设计》](../开发方案-表结构设计.md) §3.4（权威版本，不得改动；发现问题以「⚠️ 待确认」标注）。本模块共 **3 张新表 + 2 张表加列**，对应迁移 M5（DDL）与 M6（存量客户默认等级回填），基于 `3bdd9e1f06c8` 续写。

### 2.1 新表 `price_tier`（照抄 payment_method 范式 + store 维度 + 管理属性）

```sql
CREATE TABLE price_tier (
    id                 uuid PRIMARY KEY,
    store_id           uuid NOT NULL REFERENCES store(id) ON DELETE CASCADE,  -- vendor 维度
    name               varchar(100) NOT NULL,
    description        varchar(500),
    is_active          boolean NOT NULL DEFAULT true,
    is_default         boolean NOT NULL DEFAULT false,   -- 新客户自动落入的默认等级
    sort_order         integer NOT NULL DEFAULT 0,
    archived_at        timestamptz,                      -- 归档（区别于删除）
    created_by_user_id uuid REFERENCES "user"(id) ON DELETE SET NULL,
    created_at         timestamptz NOT NULL DEFAULT now(),
    updated_at         timestamptz NOT NULL,
    deleted_at         timestamptz
);
CREATE UNIQUE INDEX uq_price_tier_store_name ON price_tier(store_id, name)
    WHERE deleted_at IS NULL;
CREATE UNIQUE INDEX uq_price_tier_store_default ON price_tier(store_id)
    WHERE is_default AND deleted_at IS NULL;             -- 每 store 至多一个默认等级
```

**设计说明**：
- 等级集合是 **store（vendor）级统一维度**（Q2-A）；数量与命名完全自由（§7.1「A/B/C/D、Level 1-5、Gold/Silver 或任意名称」）。
- 两个 partial unique index 分别保证「同 store 等级名唯一（忽略软删行）」与「每 store 至多一个默认等级」；设新默认时服务层在同事务内先清旧默认。
- `archived_at` 归档态：不可再分配新客户、不出现在分配下拉；存量客户价格照常生效直至重分配。`is_active=false` 停用态：语义同归档但可一键恢复，用于临时下线。
- SQLAlchemy 模型放 `core/price_tiers/models.py`，继承 `APIModel`（自带 created_at/updated_at/deleted_at 约定）。

### 2.2 修改 `product_price` —— 加 tier 维度 + 审计（复用 append-only）

```sql
ALTER TABLE product_price
    ADD COLUMN tier_id            uuid REFERENCES price_tier(id) ON DELETE RESTRICT,
                                       -- NULL = 基础价（向后兼容：存量行全部是基础价）
    ADD COLUMN changed_by_user_id uuid REFERENCES "user"(id) ON DELETE SET NULL,
    ADD COLUMN import_job_id      uuid;                  -- 关联 store_import_job，手工改价为 NULL

CREATE INDEX ix_product_price_product_tier_created
    ON product_price(product_id, tier_id, created_at DESC);
```

**设计说明**：
- 现有 `product_price` 是 append-only 历史表（改价 = 插新行，当前价 = 最新一行），这正是 §7.8「价格审计历史」要的语义，因此在原表加维度而非另建价格表。tier 当前价 = 按 `(product_id, tier_id)` 取 `created_at` 最新一行（与现有查询同构）。
- **必须同步的代码点**：`StoreProduct.price` column_property（`core/products/models.py:191-200`）当前取「最新一条」，加 tier 后必须补 `tier_id IS NULL` 过滤，否则基础价会错误地取到 tier 价——本方案唯一「不改会静默出错」的点，代码评审必查。
- `import_job_id` 无外键（表结构设计原文如此，避免跨模块硬依赖）；查询审计时按值 join `store_import_job`。
- 若 Q1 确认选 B（无基础价）：DDL 不变，仅应用层不再写 `tier_id = NULL` 的新行。
- 大表加索引：`CREATE INDEX CONCURRENTLY` 或维护窗口（迁移 M5 风险项，CONCURRENTLY 需 alembic `autocommit_block()`）。

### 2.3 新表 `store_product_tier_availability`（三态可购性）

```sql
CREATE TABLE store_product_tier_availability (
    id                 uuid PRIMARY KEY,
    store_product_id   bigint NOT NULL REFERENCES store_product(id) ON DELETE CASCADE,
    tier_id            uuid   NOT NULL REFERENCES price_tier(id)    ON DELETE CASCADE,
    availability       varchar(16) NOT NULL DEFAULT 'AVAILABLE',    -- AVAILABLE / UNAVAILABLE
    updated_by_user_id uuid REFERENCES "user"(id) ON DELETE SET NULL,
    created_at         timestamptz NOT NULL DEFAULT now(),
    updated_at         timestamptz NOT NULL,
    deleted_at         timestamptz,
    CONSTRAINT uq_sptavail UNIQUE (store_product_id, tier_id)
);
```

**三态判定规则（应用层，需求 §7.5/§7.6）**：

| 该 (产品×等级) 的数据 | 客户看到 |
|---|---|
| 有 tier 价 且 无 UNAVAILABLE 行 | 正常价格，可购 |
| 任意价格状态 + availability=UNAVAILABLE | 不展示/不可购 |
| **无 tier 价**（无论 availability） | "请联系供应商询价"，不可加购，**不回退基础价或他 tier 价** |

**设计说明**：`availability` 用 varchar + 应用层 StrEnum（不建 PG enum，规避 `ADD VALUE` 迁移痛点，表结构设计 §一-9 决策）。缺行等同 `AVAILABLE`，因此只需为「显式不可购」写行；「未配置价格」不是本表的值，而是由「无 tier 价」推导出的第三态。

### 2.4 修改 `client` —— 等级分配

```sql
ALTER TABLE client ADD COLUMN price_tier_id uuid
    REFERENCES price_tier(id) ON DELETE RESTRICT;   -- RESTRICT 兜底"已分配等级不可删"（FR-D2）
CREATE INDEX ix_client_price_tier_id ON client(price_tier_id);
```

**设计说明**：应用层规则——新建/导入客户未指定 tier 时落入该 store 的 `is_default` 等级；「每个活跃客户必须有等级」由服务层校验（存量 client 由数据迁移 M6 统一赋默认等级，仅对启用 tier 的 store，可空跑）。tier 变更写审计（`company_audit_log`，entity_type=`CLIENT_TIER`）。删除等级的 409 校验在服务层先行，DB `RESTRICT` 仅兜底。

### 2.5 新表 `store_import_job`（客户/价格导入，FR-D7/D8）

```sql
CREATE TABLE store_import_job (
    id                   uuid PRIMARY KEY,
    store_id             uuid NOT NULL REFERENCES store(id) ON DELETE CASCADE,
    kind                 varchar(20) NOT NULL,     -- CLIENT / TIER_PRICE
    source               varchar(16) NOT NULL DEFAULT 'FILE',   -- FILE / PASTE
    file_id              uuid REFERENCES file(id) ON DELETE SET NULL,
    status               varchar(20) NOT NULL DEFAULT 'CREATED',
                         -- CREATED/PARSED/VALIDATED/COMMITTING/COMPLETED/FAILED
    column_mapping       json,
    total_rows           integer NOT NULL DEFAULT 0,
    imported_rows        integer NOT NULL DEFAULT 0,
    skipped_rows         integer NOT NULL DEFAULT 0,
    error_report         json,                     -- 逐行错误 [{row, field, error}]
    requested_by_user_id uuid NOT NULL REFERENCES "user"(id) ON DELETE RESTRICT,
    committed_at         timestamptz,
    created_at           timestamptz NOT NULL DEFAULT now(),
    updated_at           timestamptz NOT NULL,
    deleted_at           timestamptz
);
CREATE INDEX ix_store_import_job_store ON store_import_job(store_id, created_at DESC);
```

**设计说明**：
- 仿厂商域 `manufacturer_catalog_import_job`（`core/manufacturer_catalog_imports/`）的 prepare→commit 两阶段：幂等（同 job 重复 commit 返回 409）、防重复提交、逐行错误报告；不学旧 OCR webhook 直写。
- 客户导入列：客户名/客户 ID/价格等级/执照编号/执照到期日（§7.7）——后两列写入执照模块的 `client_license`（表结构设计 §3.5）；执照模块未上线时这两列跳过并在 `error_report` 中以 WARNING 级提示。价格导入列：SKU/产品名/等级名/价格/可购状态；等级名不匹配→逐行报错进 `error_report`。
- 状态机：`CREATED`（已建 job）→ `PARSED`（解析出表头与行）→ `VALIDATED`（校验完成，错误报告就绪）→ `COMMITTING`（大文件经 arq worker 异步执行）→ `COMPLETED` / `FAILED`。行数 ≤ 500 时 commit 同步执行直接到 `COMPLETED`。

### 2.6 审计与迁移序列（本模块相关部分）

- 定价变更审计由 `product_price` 行自身承载（原价 = 同 `(product_id, tier_id)` 上一行）；等级创建/删除/归档、客户 tier 变更写 `company_audit_log`，应用层 `AuditEntityTypeEnum` 追加 `PRICE_TIER` / `CLIENT_TIER` / `TIER_PRICE`，`AuditActionEnum` 追加 `TIER_ASSIGNED` / `PRICE_CHANGED` 等（表结构设计 §3.5.6；`details` 列放宽为 text 属迁移 M10，跨模块共用）。
- 迁移排期（表结构设计 §四）：**M5** `add_price_tier_tables`（本节全部 DDL，风险中：product_price 大表索引）→ **M6** `backfill_default_tier_for_existing_clients`（数据迁移，低风险，可空跑）。M5/M6 全部向后兼容，老代码可与新 schema 共存，支持先 `alembic upgrade` 再滚动发版。
- ⚠️ 环境注意：开发库 = v20260705 代码空库 `upgrade head` 或从 `preprod_main_full_20260716.dump` 恢复；**旧 css_dev（GitHub main 版 + db_compare 补丁）已作废，禁止在其上跑这些迁移**。

## 3. 接口设计

### 3.0 总览

约定（均已按 v20260705 代码核实）：
- 所有路由挂在 `/api` 网关下，受 `X-API-KEY` 守卫；鉴权 `Security(check_access_token)`（Bearer access token）；细粒度权限 `Depends(check_permissions(required_permissions=[...]))`，权限串沿用 `<action>__<entity>` 形态（如 `view__product`）。
- 新增 api_entity `price_tier`（种子迁移，表结构设计 §3.1 迁移②），派生权限 `create__price_tier` / `view__price_tier` / `edit__price_tier` / `delete__price_tier`，授予 CEO/CFO/Manager（Q7-A 下不授予 Compliance Manager）。
- 响应信封沿用 `app/pkg/responses.py`：`SuccessOut = {"success": true}`、`ListResponse = {"items": [...]}`、`PaginatedListResponse = {"count": n, "items": [...]}`；错误 `ErrorOut = {"type": "...", "message": "..."}`（由 `HTTPErrorFactory` 产出）。字段命名 snake_case。

### 3.1 等级管理

#### 3.1.1 GET `/vendors/{vendor_id}/price-tiers` — 等级列表

- **用途**：等级管理页主数据源；分配下拉（前端过滤 `is_active && !archived_at`）。
- **请求参数**：path `vendor_id: UUID`；query `include_archived: bool = false`。
- **响应体**（`ListResponse[PriceTierOut]`，200）：

```json
{
  "items": [
```

#### 3.4.1 R1 改造 POST `/vendors/{vendor_id}/products`（产品列表）

#### 3.4.3 R3/R4 改造下单链路（餐厅端 / 供应商代下）

- **位置**：`POST /restaurants/{restaurant_id}/orders`（`add_restaurant_order` → `RestaurantsOrdersService`）与 `POST /vendors/{vendor_id}/orders`（`create_order` → `StoresOrdersService`），两者共享 `OrdersService` 底座；落价快照点 `core/stores/orders/services.py:217` → `create_order_products_price_history`（`core/orders/services.py:1636`）。

  1. 逐行取价源改为「该 client 的 tier 当前价」（vendor 未启用 tier——即无任何 price_tier 行——时维持基础价，普通供应商零影响）；

1. vendor CEO：建 4 个等级（A/B/C/D）→ 产品页配等级价 → 客户档案分配等级 → 以该客户身份登录 → 列表/详情见对应 tier 价 → 加购下单 → vendor 确认订单价格一致。
2. 缺价链路：产品对客户所在等级不配价 → 客户端显示「请联系供应商询价」、加购禁用 → 直接调接口提交被 400 → 页面按 type 显示文案（中英双语言各跑一遍）。
3. 批量导入：上传 200 行价格文件（含错行）→ 映射 → 校验错误报告可见 → commit → 矩阵页价格生效、错误行可下载；同文件重复 commit 提示已提交。
4. 防误删：删除有客户的等级 → 409 弹窗 → 批量重分配客户 → 删除成功。
5. 权限：以 Salesman（未授权 tier 权限）登录 → Sidebar 无入口、直达 `/price-tiers` 显示 NotFound（AllowedTo no 分支）。

### 6.4 回归与性能
