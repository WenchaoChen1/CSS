# Ocean Island 酒类供应商系统增强需求

> 译自《Ocean Island Liquor Vendor System Enhancement Requirements.pdf》（15 页，2026-07-27 收到，**本版为正式修订版，替换 2026-07-16 的草稿译文**）。原 PDF 存放于本目录同名文件。本版无批注（旧草稿中 Michael Zhang 的 4 条批注问题已被本版正文直接回答）。
> 翻译约定：Liquor Vendor=酒类供应商；Tier=价格等级；License Hold=执照保留（合规挂起标记）；Verified=已核验；Delivered=已交付。

---

## 1. 执行摘要

CSS 将新增**酒类供应商（Liquor Vendor）**作为第七种实体类型。

该模块将复用标准 Vendor 基础能力，同时使酒类专属的定价、执照合规与订购规则**与现有餐饮（Food & Beverage）Vendor 工作流保持分离**。

首期发布包含：

- 面向 Liquor Vendor 用户的 30 天持久登录；
- 英文与简体中文订购体验；
- Vendor 级产品类目管理；
- 客户价格等级，其中 **Tier A 作为默认与回退等级**；
- 客户与产品批量导入；
- 简化的订单提交流程；
- 订单在交付（Delivered）前的动态调价；
- 酒类执照上传、人工审核、到期提醒与订购限制。

## 2. 范围

### 2.1 首期范围内

首期发布包含：

- 可复用的 Liquor Vendor 实体及相关权限；
- Vendor Settings 下的产品类目管理；
- 英文与简体中文类目标签；
- 安全的 30 天持久会话；
- 核心订购流程的简体中文本地化；
- 价格等级配置与客户分配；
- Tier A 默认与回退定价；
- 按等级的产品定价与可购性；
- 客户与产品导入（不含导出）；
- Liquor Vendor 订单审核、提交与确认；
- 未达到"已交付（Delivered）"状态订单的自动价格更新；
- 执照档案、人工核验、文档留存、到期提醒、订单阻断与执照保留（License Hold）；
- 执照相关通知与审计记录。

### 2.2 首期范围外

以下内容**不**包含在首期发布中：

- 西班牙语本地化；
- 客户或产品导出；
- 价格变更历史或定价审计日志界面；
- 专门的执照合规仪表盘或报表导出；
- 仅凭 OCR 结果自动批准执照；
- 管理员越权解除执照限制（Administrative override）；
- 政府或第三方执照核验集成；
- 面向消费者的直接酒类销售；
- 消费者年龄验证；
- 酒类专属税费调整；
- 酒类配送路线合规规则；
- Shipped By 与 Payment Method 的共享 Settings 库。

## 3. Liquor Vendor 实体与权限

### 3.1 实体模型

新增 **Liquor Vendor** 作为 CSS 第七种实体类型。

该实体必须继承标准 Vendor 功能，包括：

- 产品目录管理；
- 客户管理；
- 订单处理；
- 发票与对账单管理；
- 团队与用户管理；
- 通知。

**酒类专属逻辑不得改变现有餐饮（Food & Beverage）Vendor 的行为。**

### 3.2 酒类专属权限

获授权的 Liquor Vendor 用户可以被允许：

- 管理价格等级与按等级的产品价格；
- 分配客户价格等级；
- 管理产品类目；
- 查看与编辑客户执照信息；
- 上传与审核执照文档；
- 批准或驳回执照；
- 要求更新执照信息；
- 查看执照审核历史。

执照批准与驳回权限必须仅限获授权的 Vendor 角色。

### 3.3 产品类目管理

产品类目必须通过 **Vendor Settings** 下的**共享类目库**管理。

获授权用户必须能够：

- 创建与编辑类目；
- 启用与停用类目；
- 存储英文与简体中文类目名称；
- 在创建或编辑产品时选择已有类目；
- 查看某类目当前是否已被产品使用。

已被一个或多个产品使用的类目**不得被永久删除**。

Vendor 可停用类目以阻止其被分配给新产品。已分配该类目的既有产品必须保持不变。

## 4. 持久登录会话

Liquor Vendor 用户必须保持登录状态最长 30 天，除非：

- 用户手动登出；
- 用户重置或修改密码；
- 账号被停用；
- 管理员吊销会话；
- 安全事件要求重新认证；
- 30 天会话到期。

会话时长应**按实体可配置**，以便该能力可复用于未来的其他酒类供应商。

要求：

- 关闭并重新打开浏览器不得终止有效会话；
- 登出、密码重置、账号停用或管理员吊销必须立即终止会话；
- 系统应使用短时效 access token 配合安全的 refresh token 轮换；
- 会话必须支持服务端吊销；
- 管理员必须能够终止活跃会话。

## 5. 本地化

首期发布必须支持：

- 英文；
- 简体中文。

可以为指定的 Ocean Island 用户将简体中文设为默认订购语言。英文必须保持为回退语言。

以下区域必须支持简体中文：

- 登录与身份认证；
- 导航；
- 产品类目；
- 产品目录与产品详情；
- 搜索与筛选；
- 订单审核（Order review）；
- 订单提交与确认；
- 订单历史与状态；
- 通知；
- 校验与错误消息；
- 执照状态与到期消息；
- 价格与单位标签。

附加要求：

- UI 翻译必须存放在集中的本地化文件中；
- Vendor 录入的产品信息按录入语言显示，除非提供了翻译值；
- 当中文 UI 翻译缺失时，系统必须回退到英文。

## 6. 客户价格等级

### 6.1 等级配置与客户分配

Vendor 必须维护**一套共享的**客户价格等级，例如：

- Tier A；
- Tier B；
- Tier C；
- Tier D。

等级的数量与名称必须可配置。

每个活跃客户必须有一个已分配的价格等级。**客户不得查看或更改自己的等级分配。**

获授权用户必须能够：

- 创建与重命名等级；
- 启用与停用等级；
- 调整等级排序；
- 归档未使用的等级；
- 在创建客户时分配等级；
- 在导入客户时分配等级；
- 从客户档案（Client Profile）更新等级；
- 批量更新客户等级。

当新建或导入的客户没有有效价格等级时，系统必须**自动分配 Tier A**。

当前仍分配给客户的等级，在受影响客户重新分配之前**不得归档**。

### 6.2 产品定价与可购性

每个产品可以为任意活跃等级配置价格。

**每个活跃产品都必须配置 Tier A 价格；Tier A 是默认与回退价格。**

适用规则如下：

1. 若产品对客户所在等级**显式标记为不可购**，则该产品不可下单；
2. 若客户所分配等级存在价格，系统使用该价格；
3. 若所分配等级的价格缺失，系统使用该产品的 **Tier A 价格**；
4. 若 Tier A 价格缺失，该产品**不能发布，也不能被下单**。

| 客户等级 | 所在等级价格 | Tier A 价格 | 结果 |
|----------|--------------|-------------|------|
| Tier C | 已配置 | 已配置 | 使用 Tier C 价格 |
| Tier C | 缺失 | 已配置 | 使用 Tier A 价格 |
| Tier C | 不可购 | 已配置 | 产品不可下单 |
| 任意等级 | 缺失 | 缺失 | 产品不能发布 |

该结构允许不同产品配置**不同数量**的等级价格，同时保持每客户一个等级分配。

例如：

- 产品 1 可以配置 Tier A、Tier B、Tier C 价格；
- 产品 2 可以只配置 Tier A、Tier B 价格；
- 当 Tier C 客户查看产品 2 时，因 Tier C 价格缺失，系统显示 Tier A 价格。

### 6.3 价格应用

- 客户必须只能看到适用于自己所在等级的价格与可购性；
- 相同定价规则必须一致应用于产品列表、产品详情、订单审核、采购订单（Purchase Order）与发票；
- **订单提交时客户所处的等级必须随订单存储**；
- 更改客户等级影响未来订单，**不改变既有订单**。

## 7. 客户与产品导入

### 7.1 客户导入

获授权用户必须能够通过结构化 CSV 或 Excel 模板导入客户。

**最终模板与字段映射必须在开发定稿前与 Ocean Island 确认。**

支持字段可包括：

- 客户 ID 或客户编码；
- 企业名称；
- 联系信息；
- 企业地址；
- 指定销售员；
- 分配的价格等级；
- 执照编号；
- 执照类型；
- 执照生效日期；
- 执照到期日期。

导入规则：

- 若价格等级为空或无效，分配 Tier A；
- **执照文件不随导入携带**，必须从客户档案手动上传；
- 校验必填字段、重复客户、等级取值与日期格式；
- 对无法导入的记录提供**行级错误报告**。

### 7.2 产品与等级价格导入

**Product ID 应作为主匹配标识。**

- 若 Product ID 匹配到已有产品，更新该产品；
- 若 Product ID 是新的，在通过校验的前提下创建新产品；
- 产品名称或 SKU 不得作为主匹配键。

支持字段可包括：

- Product ID；
- 产品名称；
- 类目；
- 品牌；
- 计量单位；
- Tier A 价格；
- 其他等级价格；
- 产品状态。

导入必须校验：

- 重复的 Product ID；
- 类目取值；
- 必填的 Tier A 价格；
- 等级取值；
- 数字与货币格式。

客户与产品**导出**不包含在首期发布中。

## 8. 订购与价格锁定

### 8.1 Liquor Vendor 订购流程

Liquor Vendor 的订购流程必须为：

**选择产品 → 订单审核 → 提交订单 → 订单确认**

要求：

- 提交前提供一次最终审核；
- 展示产品、单位、数量、适用价格、合计与备注；
- 在用户完成最终提交之前，**不得创建或传输订单**；
- 提交成功后展示订单号与确认信息；
- 餐厅提交环节使用"订单（Order）"或"采购订单（Purchase Order）"术语；
- 不得将餐厅提交环节称为"发票（Invoice）"；
- **不得改变其他 Vendor 类型的订购流程**。

### 8.2 交付前的价格更新

目录（catalog）价格变更必须更新处于活跃状态的 Liquor Vendor 订单，直至订单到达**已交付（Delivered）**状态。

该规则适用于：

- 已提交但尚未确认的订单；
- 已确认但尚未交付的订单；
- 其他任何未达到 Delivered 状态的活跃订单。

当适用的目录价格发生变更时，系统必须：

- 更新活跃订单上对应的产品价格；
- 重新计算受影响的行项目小计；
- 重新计算小计；
- 重新计算订单总额及其他依赖价格的金额；
- 使用随订单存储的客户等级；
- 在所分配等级价格缺失时应用 Tier A 回退规则；
- **在交付前向客户展示更新后的价格与订单总额**。

订单到达 **Delivered** 状态后即价格锁定。

交付后：

- 后续目录价格变更不得修改该订单；
- 后续目录价格变更不得修改最终发票；
- 已交付订单与发票必须保留**交付时记录的最终价格**。

### 8.3 订购验收标准

- 无有效价格等级的客户被分配 Tier A；
- 所在等级价格缺失时回退到 Tier A；
- 对客户所在等级标记不可购的产品不能被下单；
- 无 Tier A 价格的产品不能发布或被下单；
- 最终订单审核准确展示产品、数量、价格与合计；
- 未达到 Delivered 状态的订单在适用目录价格变更时被正确重新计价；
- 已交付订单保留交付时记录的最终价格。

## 9. 客户酒类执照合规

### 9.1 执照档案

每个从事相应酒类交易的餐厅客户，必须维护该交易所需的执照。

客户档案（Client Profile）必须存储：

- 执照持有人法定名称；
- 企业名称；
- 执照或许可证编号；
- 执照类型；
- 签发机构；
- 签发州或司法辖区；
- 生效日期；
- 到期日期；
- 执照文档；
- 核验状态（Verification status）；
- 审核人；
- 审核日期；
- 审核备注；
- 通知联系信息。

执照类型与各司法辖区的具体要求，必须由 Ocean Island 或其法务/合规代表确认。

### 9.2 核验状态与到期状态

执照的核验与到期必须作为**两个独立的状态**管理。

| 状态类型 | 取值 | 规则 |
|----------|------|------|
| 核验状态（Verification Status） | Not Submitted（未提交）、Pending Review（待审核）、Verified（已核验）、Rejected（已驳回） | 由工作流或获授权审核人更新 |
| 到期状态（Expiration Status） | Active（有效）、Expiring Soon（即将到期）、Expired（已过期）、Not Available（不可用） | 由到期日期自动计算 |

规则：

- 上传新执照或替换执照会把核验状态置为 Pending Review；
- 获授权用户可核验、驳回或要求更新信息；
- 用户不得手动编辑到期状态；
- 系统必须定期重新计算到期状态；
- Expiring Soon 的天数必须可配置；
- 建议默认值为到期前 7 天；
- 一张执照可以同时处于 Verified 且 Expiring Soon。

### 9.3 文档上传与留存

系统必须：

- 支持 PDF、JPG、JPEG、PNG 上传；
- 使用安全的文件存储与基于角色的访问控制；
- 实施文件大小限制与恶意软件扫描；
- 要求执照文档从客户档案**手动上传**；
- 执照续期时**另存为新记录**，而不是覆盖原记录；
- 留存历史执照记录与文档；
- 允许将旧记录标记为 Replaced（已替换）或 Archived（已归档）；
- 留存执照编号、日期、状态、备注与审核历史。

首期发布中，标准用户界面**不得提供永久删除**功能。

### 9.4 人工核验

首期发布采用人工执照核验。

获授权的 Ocean Island 用户必须能够：

- 审阅已上传的执照文档；
- 将文档与录入信息比对；
- 批准执照；
- 驳回执照；
- 要求更新信息；
- 添加审核备注。

政府或第三方执照核验集成可作为未来增强项。

### 9.5 到期提醒

获授权的 Liquor Vendor 用户必须能够在 **Vendor Settings** 下配置：

- 是否启用到期提醒；
- 提醒间隔；
- 通知发送时间；
- 是否在到期日当天发送提醒；
- 启用的通知通道。

建议的默认提醒间隔：

- 到期前 60 天；
- 到期前 30 天；
- 到期前 14 天；
- 到期前 7 天；
- 到期前 1 天；
- 到期日当天。

提醒计划必须遵循该 Liquor Vendor 配置的**时区**。

客户侧通知收件人必须在客户档案中配置。指定的 Ocean Island 管理员或审核人也可以接收通知。

支持的通道：

- 站内通知；
- 邮件；
- 短信（启用时）。

当执照续期或被替换时，系统必须：

- 重新计算提醒计划；
- 避免针对同一执照、同一收件人、同一提醒间隔发送重复通知。

### 9.6 订购资格

客户仅当至少有一张当前执照同时满足以下条件时，才可以提交 Liquor Vendor 订单：

- **已核验（Verified）**；且
- **有效（Active）或即将到期（Expiring Soon）**。

**Expiring Soon（即将到期）**

当执照处于 Expiring Soon 时，系统必须：

- 显示可见的警告；
- 显示到期日期或剩余天数；
- 请客户提供更新后的执照；
- 继续允许该客户浏览产品并下单。

**Blocked Ordering（订购阻断）**

当不存在有效且已核验的执照时，系统必须阻断 Liquor Vendor 订购，包括以下情形：

- Not Submitted（未提交）；
- Pending Review（待审核）且无其他有效执照；
- Rejected（已驳回）；
- Expired（已过期）。

订购被阻断时，系统必须：

- 禁用加入订单（Add to an order）；
- 禁用结算（Checkout）；
- 禁用最终订单提交；
- 说明客户为何不能下单；
- 指引客户联系 Ocean Island 或提交更新后的执照信息。

若替换执照处于 Pending Review 而既有已核验执照仍然有效，客户可以继续凭既有执照订购。

**执照限制仅适用于 Liquor Vendor 订购。**

推荐的阻断提示文案：

> Your liquor license is expired or is not currently valid. Please contact Ocean Island and update your license information before placing an order.
> （您的酒类执照已过期或当前无效。请联系 Ocean Island 并更新您的执照信息后再下单。）

### 9.7 既有订单与执照保留（License Hold）

若客户执照在订单提交之后、完全交付之前过期，该订单**不得被自动取消**。

系统必须将订单中**未交付的部分**置于 **License Hold（执照保留）**。

License Hold 生效期间，系统必须：

- 保持订单对客户与 Liquor Vendor 可见；
- 显示保留原因；
- 阻止未交付条目的确认、发货或交付；
- 请客户提供更新后的执照；
- 通知相应的 Ocean Island 用户。

续期执照核验通过后，系统必须解除 License Hold 并允许订单继续。

对部分交付的订单：

- 已交付条目保持完成且不变；
- 未交付条目保持 License Hold。

已完全交付的订单不得受后续执照过期影响。

执照过期不得阻止：

- 退货（Returns）；
- 冲抵（Credits）；
- 针对已交付订单的退款（Refunds）。

**License Hold 必须实现为合规标记（compliance flag），而不是新增一种标准订单状态（Order Status）。**

### 9.8 执照验收标准

- 用户可以安全地上传与审核客户执照；
- 核验状态与到期状态正确更新；
- 持有 Expiring Soon 执照的客户收到警告且可以继续订购；
- 没有已核验且有效执照的客户不能提交 Liquor Vendor 订单；
- 执照续期在不删除历史的前提下更新当前执照与提醒计划；
- 未交付订单正确进入与退出 License Hold。

## 10. 通知、安全与审计

### 10.1 通知

首期发布**仅包含执照相关通知**：

- 新执照或替换执照已上传、待审核；
- 执照被批准；
- 执照被驳回；
- 要求更新执照信息；
- 执照即将到期；
- 执照已过期。

导入错误必须体现在导入结果中。

以下事件在首期发布中**不**需要单独通知：

- 产品价格变更；
- 客户等级变更；
- 被阻断的订购尝试。

### 10.2 访问与审计

系统必须：

- 通过基于角色的访问控制保护执照文档、价格等级分配、产品定价与内部审核备注；
- 阻止客户访问其他客户的执照、定价或内部备注；
- 记录执照上传与替换；
- 记录执照状态变更；
- 记录审核人、审核日期与原因或备注；
- 记录客户价格等级分配变更。

**专门的价格历史日志与管理员越权（override）工作流不包含在首期发布中。**

## 11. 非功能性需求

- **性能**：等级定价与执照校验不得显著拖慢目录浏览或结算体验；导入必须展示进度与行级错误。
- **可靠性**：失败的通知必须被记录并重试；未来的外部核验服务故障不得导致执照限制被绕过。
- **可扩展性**：设计必须支持多个 Liquor Vendor、各 Vendor 独立的等级集合、多司法辖区、每客户多执照与更多语言。
- **可用性**：中文用户必须能够在不依赖英文的情况下完成核心订购流程；执照警告必须清楚说明所需操作。
- **安全**：系统必须使用安全的会话管理、受保护的文档存储、最小权限授权，以及**服务端强制执行**定价与执照规则。

## 12. 依赖项与待确认事项

- Ocean Island 的客户与产品导入样例文件；
- 最终导入字段映射；
- 预期的产品与客户数量级；
- 所需执照类型与司法辖区；
- 各司法辖区的合规要求；
- 指定的执照审核人；
- 客户通知联系人；
- 最终提醒间隔；
- 所需通知通道；
- 邮件与短信服务可用性；
- 简体中文翻译的审校；
- 与现有 CSS 认证、目录、客户、订单、发票与通知服务的兼容性。

## 13. 完成的定义（Definition of Done）

首期发布在满足以下条件时视为完成：

- Liquor Vendor 作为可复用的第七种实体可用，且不改变现有 Vendor 工作流；
- 获授权用户可以管理类目、价格等级、客户、产品与导入；
- Tier A 默认与回退定价在目录、订单、采购订单与发票中一致生效；
- 未达到 Delivered 状态的订单在适用目录价格变更后正确更新；
- 已交付订单与最终发票保留交付时记录的价格；
- Ocean Island 用户可以在批准的会话期长内保持登录；
- 核心餐厅订购流程提供英文与简体中文；
- 执照上传、历史、审核、状态计算、提醒、订单阻断与 License Hold 按定义工作；
- 权限与执照审计记录在服务端强制执行；
- 安全、权限、导入、定价、订购、通知与回归测试全部完成；
- Ocean Island 完成用户验收测试并批准发布。
