## 一、总体业务约束（所有功能项共同遵守）

1. **Liquor Vendor 只是公司类型层面的新增，业务走现有 Vendor 业务线。** 它是 `company_type` 表中 `category='VENDOR'` 下的第 7 行种子数据，不是独立业务分类；vendor 侧的产品管理、订单管理、发票/月结、团队、报表等能力全部直接继承现有 Vendor 链路，**零改动生效**。酒类专属逻辑不得改变现有餐饮 Vendor 行为（§3.1）。
2. **不影响现有 Vendor / Restaurant。** 全部迁移为向后兼容的新表/加列/种子数据；既有 6 类实体的 onboarding、下单、发票链路必须回归通过。
3. **价格等级、产品类目、执照合规、动态调价仅 Liquor Vendor 生效。** 未启用的普通 vendor 读价/下单/发票维持现状（默认价、无类目库约束、无执照校验、提交即锁价），集成测试要求"普通供应商全流程与改造前完全一致（零回归）"。
4. **Liquor Vendor 的定价基准是 Tier A**（§6.2）：每个活跃产品必须配置 Tier A 价；客户所在等级缺价时**回退 Tier A**；产品无 Tier A 价则不能发布也不能下单。客户只见适用于自己等级的价格与可购性，**看不到等级名称、他等级价格与内部信息**（§6.3/§10.2）。
5. **多语言设置（原"中文本地化"）是全站语言能力**，本期只交付简体中文（zh，西语明确首期范围外 §2.2），架构按多语言可扩展设计。
6. **餐厅（采购侧）的订单/产品页面兼容 Vendor 与 Liquor Vendor 两种业务线**：普通 vendor 照常默认价、无执照概念；liquor vendor 按客户 tier 展示价格与可购性、受执照阻断（含中文提示与上传引导），且**未达 Delivered 的订单随目录价动态重算，Delivered 后锁价**（§8.2）。

```

                    │  02 持久会话（实体级 TTL 配置）        │
                    │  03 多语言设置（全站，本期 zh）        │
                    └──────────────────────────────────────┘
  现有 Vendor 业务线（产品/订单/发票/团队/报表 —— 不动）
        │
        ├── 普通 Vendor ──────────── 默认价格、提交锁价、无执照/类目约束（保持原样）
        │
        └── 01 Liquor Vendor（新 company_type，继承全部 Vendor 能力）
                ├── 04 价格等级（Tier A 默认/回退 + 交付前动态调价，仅 liquor vendor）
                ├── 05 执照合规（仅 liquor vendor）
                └── 06 产品类目管理（Vendor Settings 共享类目库）

  餐厅采购侧（订单/产品）：同一套页面兼容两种业务线（按 vendor 是否启用 tier/合规自动分支）
```

### 4. 客户价格等级（Tier A 默认/回退 + 交付前动态调价）

> 📁 [04-价格等级/](04-价格等级/) · [需求](04-价格等级/需求.md) · [开发方案](04-价格等级/开发方案.md)
> ⚠️ **本模块因正式版需求出现两处模型反转，开发方案需回改**（见 §〇）：① Tier A 即默认与回退价（非"绝不回退"）；② 交付前动态调价（非"提交即锁价"）。以下已按新口径描述，估时标"待重估"。

酒类供应商可自定义客户价格等级（Tier A/B/C/D…，数量与名称可配置）：每个活跃客户分配一个等级（**客户不可见/不可改自己的等级**）；按"产品×等级"配置差异化价与可购性。**取价规则（§6.2）**：产品对客户等级显式不可购→不可下单；有所在等级价→用之；缺所在等级价→**回退 Tier A 价**；无 Tier A 价→产品不能发布/下单。**动态调价（§8.2）**：目录价变更自动重算所有**未达 Delivered** 的订单（含已提交、已确认）——更新行价、重算行小计/小计/订单总额，用随订单存储的客户等级取价，缺价走 Tier A 回退，交付前向客户展示更新后价格；订单 **Delivered 后锁价**，已交付订单与最终发票保留交付时价格。

**业务约束**：**仅 liquor vendor 使用**——等级为 vendor 级统一维度；未启用 tier 的存量 vendor 读价/下单/锁价维持现状（零回归）。客户界面无"等级"概念，响应不携带等级名/他等级价。**动态调价是最高回归风险项**（改动订单→发票→月结取价与重算底座，且反转现有"提交锁价"语义）。

| 子项分类 | 描述 | 层 | 估时 |
|----------|------|----|------|

### 5. 酒类执照合规

> 📁 [05-执照合规/](05-执照合规/) · [需求](05-执照合规/需求.md) · [开发方案](05-执照合规/开发方案.md)
> ⚠️ **本模块因正式版需求缩减范围，开发方案需回改**（见 §〇）：合规仪表盘/报表导出、管理员 override 移出首期；通知收敛为 6 类执照事件。

收集、审核、跟踪并监控客户（餐厅）酒类执照：`client_license` 执照档案（§9.1 的 ~14 字段，1:N 多执照）+ **两套独立状态**（核验：Not Submitted/Pending Review/Verified/Rejected；到期：Active/Expiring Soon/Expired/Not Available，由到期日自动计算，Expiring Soon 天数可配置默认 7 天）+ 人工审核工作流（批准/驳回/要求更新/备注）+ 每日到期扫描与 60/30/14/7/1/0 档三通道提醒（按 vendor 时区、防重发）。**订购资格（§9.6）**：至少一张执照 Verified 且 Active/Expiring Soon 才可下单；Expiring Soon 显警告但允许下单；Not Submitted/Rejected/Expired/无有效执照的 Pending 时阻断加购/结算/提交。**License Hold（§9.7）**：已提交订单遇执照过期不自动取消，未交付部分置 License Hold（合规标记，非新订单状态），按行处理部分交付，续期核验通过后解除；退货/冲抵/退款不受限。

**业务约束**：**仅对启用执照合规的酒类 vendor 生效**——非酒类 vendor 恒放行，链路零影响。执照挂**餐厅客户档案**；被阻断展示中英双语提示与上传引导（文案与模块 03 共用，推荐文案见 §9.6）；客户不可见他客执照与内部审核备注（§10.2 RBAC）。校验 fail-closed；文件安全存储（PDF/JPG/JPEG/PNG，大小限制，见 N8 恶意软件扫描待确认）走 S3 私有前缀；续期另存新记录、留存历史，标准 UI 无永久删除。
