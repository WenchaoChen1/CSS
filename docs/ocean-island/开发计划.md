## 一、总体节奏

沿用需求文档的 4 阶段划分，前面加一个**阶段 0（决策与清障）**。阶段 1 内三条线（实体/会话/多语言）互相独立可并行；阶段 2 与阶段 3 的后端领域建模也可部分并行（不同 domain，无表冲突）。

```
阶段0  决策+安全清障      ▓▓            ~1.5 周
阶段1  基础（实体/会话/多语言）▓▓▓▓▓▓        3~4 周（三线并行）
阶段2  价格等级          ▓▓▓▓▓▓▓▓      4~5 周
阶段3  执照合规          ▓▓▓▓▓▓▓▓▓▓    5~6 周（部分与阶段2并行可压缩）
阶段4  可选自动化（OCR等）  ▓▓▓▓          2~4 周（可延后）
```

- **串行走完约 15~19 周**；若 2 名后端 + 2 名前端并行（阶段 2/3 后端错开领域、前端错开页面），**可压缩到 10~12 周**（不含阶段 4）。
- 每阶段结束出一个可演示里程碑，尽早让 Ocean Island 介入验收（尤其 tier 定价与执照工作流的交互方式）。

## 七、测试与质量计划

- **TDD**：每个新 service/repository 先写测试（项目规则强制），后端跑 `make dev_test k=<name>` 增量验证，合入前 `make test` 全量 + `make lint`。
- **覆盖率**：新增领域（price_tiers、licenses）单元+集成覆盖 ≥80%。
- **关键回归**（每阶段必跑）：
  - 阶段 1：现有 6 类实体 onboarding 不受影响；现有用户登录/刷新不受会话重构影响（老 token 兼容或强制重登方案二选一，需在 B1 决策）。
  - 阶段 2：订单→发票→月结单全链路金额回归（取价底座被改）。
  - 阶段 3：非酒类 vendor 的下单链路不被执照校验波及（校验只对启用合规的 vendor 生效）。
- **E2E**：中文下单流程、tier 价差异、执照阻断三条主流程各建 Playwright 用例；按 320/768/1440 断点截屏验证中文排版不溢出。
- **安全测试**：预签名 URL 越权访问、他客执照/他 tier 价格越权读取、override 未授权调用（对应 FR-I2）。
- **性能**：产品列表按 tier 取价的查询计划检查（需求 §12.1）；到期扫描在预期客户量下的执行时长。

## 八、部署与迁移注意（交接环境特有）

- **所有迁移只能对齐"代码 schema"演进**：本地 `css_dev` 含快照 hack（`businesstype.MANUFACTURER`、`company.user_id` 可空），**不得对导入快照的库随意跑 alembic downgrade**；新迁移合入前先在干净 `postgres` 库验证 `alembic upgrade head`。
- 后端代码变更需重建镜像（`redeploy.ps1`）；env 变更仅需重启容器。
- test/uat 环境在 AWS（EC2+RDS 三栈独立部署）；注意 test 环境已知的用户密码 salt 问题（见项目记忆）。
- **GitLab 新版源码风险**：若在开发中拿到原团队更新代码，先做 diff 复核 tier/license 相关结论再继续。

## 九、依赖清单（需 Ocean Island / 产品侧提供）
