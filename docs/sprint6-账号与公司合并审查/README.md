## findings.json 字段

| 字段 | 含义 |
|---|---|
| `id` | 编号。F 开头是第 1 版发现的问题，N 开头是之后各版新发现的问题；编号不复用 |
| `lab` | 报告里的别名，例如 `H1`、`H6′`、`M1`；删表前提复核新增的标为 `删表` |
| `sev` / `psev` / `orig` | 当前级别 / 上一版级别 / 首次发现时的级别：`high`、`medium`、`low` |
| `st` / `prev` | 当前状态 / 上一版状态：`new`、`still_present`、`partially_fixed`、`worse`、`fixed`、`obsolete`、`accepted`（按设计接受）、`waived`（按已确认的前提不计入） |
| `text` | 问题标题 |
| `note` | 最近一次复核的说明，含 `文件:行号` 证据；多次补充按时间追加 |
| `hash` / `by` | 引入问题的提交 / 作者 |
| `file` | 主要位置 |
| `fix` | 修复提交 |
| `chg` | 本版是否有变化 |
| `reply` / `replyb` / `replyv` | 只有团队答复过的条目才有（第 1、2 批 48 条，第 3 批 145 条）：团队原话（逐字照录）/ 第几批答复 / 一句话核实结论。页面在该条问题下面直接显示，`apply_recheck.py` 会原样带到下一版 |
| `done` / `remain` | 只有「部分修复」的条目才有：已经修好的部分 / 还剩的问题，各一两句话。页面在该条问题下面直接显示，报告「〇-C」逐条列出。`apply_recheck.py` 只在状态仍是部分修复时带到下一版，**每版复核后要按新代码重写**（当前按后端 `bd254f8e`、前端 `f9ae662e` 核对） |

未关闭 = `st` 不是 `fixed`、`obsolete`、`accepted`、`waived`。

本版新发现 = `prev` 为空。本版新发现、又在本版内被修好或部分修好的条目，`st` 直接是 `fixed` / `partially_fixed`（例如第 5 版的 N98、N100）。
