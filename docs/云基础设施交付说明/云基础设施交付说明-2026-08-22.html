整套基础设施具备以下特征：

  • 全量代码化管理（IaC）：所有 AWS 资源统一纳管，任何变更可追溯、可复现；生产关键资源（数据库、负载均衡）开启删除保护。
  • 生产隔离：生产环境拥有独立的网络（VPC）、独立的数据库实例（跨可用区高可用）、独立的发布审批闸口，与所有非生产环境互不可见。
  • 数据保护：数据库自动备份保留 35 天并支持按时间点恢复；存储全部加密；非生产环境使用脱敏数据。
  • 自动化发布：测试与验收环境提交代码即自动构建、自动部署；生产发布需人工确认，镜像版本化、分钟级回滚。

2总体架构

全部资源部署于 AWS us-east-1（北弗吉尼亚）区域，分为两套完全隔离的虚拟私有网络（VPC）：生产一套、非生产一套。所有应用服务器与数据库均位于私有子网、无公网地址，对外只暴露负载均衡器（ALB）。

三条访问铁律

  • SSH 只经堡垒机：应用服务器不开公网 22 端口，管理访问必须经堡垒机跳板（仅白名单 IP 可达）。
  • Web 只经本环境负载均衡：每个环境一个独立 ALB，环境之间互不借道。
  • 数据库只在内网：RDS 无任何公网暴露，仅接受本环境应用服务器与堡垒机的内网连接。

4应用运行形态

每个环境在一台应用服务器上以容器化方式运行三组独立服务栈，可分别独立更新：

服务栈包含服务职责
前端栈 Web 前端（单页应用） 用户界面；同源反向代理到后端，避免跨域问题
后端栈（11 个容器） 主 API、聊天服务、通知服务、异步任务、短信发送、邮件发送、AI 助手、产品目录识别（OCR）等 全部业务逻辑；按职责拆分为独立容器，互不阻塞
中间件栈 Redis 缓存、RabbitMQ 消息队列、Kafka 事件流 缓存、通知投递、验证码等事件消息

数据库不在服务器上，统一使用 AWS 托管的 RDS PostgreSQL——主业务库与 OCR 库分库存放（详见第 5 章）。

技术栈

  • 后端：Python / FastAPI，容器化部署，多进程 + 异步任务队列
  • 前端：React 19 + TypeScript，构建产物为静态资源 + Nginx
  • 数据库：PostgreSQL 16（AWS RDS 托管）
  • 基础设施：全量代码化管理（IaC）

7发布与运维

发布流程

  1. 开发
    提交代码到对应环境分支
    自动触发 CI：代码检查 → 单元测试 → 构建容器镜像 → 推送镜像仓库（版本化编号 + 浮动标签双轨）
  2. 系统
    test / uat：自动部署
    数据库迁移（uat 迁移前自动打快照）→ 通过 AWS 系统通道下发部署指令（全程无 SSH、无长期密钥）→ 拉取镜像 → 滚动更新 → 健康检查冒烟
  3. 负责人
    prod：人工确认后发布
    主分支提交只构建镜像不部署；发布需在流水线上手动触发（人工闸口），流程与自动部署一致
  4. 系统
    发布完成，通知送达
    部署结果自动推送消息通知；如需回滚，选择上一个版本化镜像重新部署，分钟级完成

场景恢复手段恢复目标

日常监控

指标越过阈值 → 告警触发 → 邮件即时送达运维负责人。核心告警包括：服务不可用（健康目标为零，比用户报障更早发现）、应用报错（5xx）、响应变慢（P95 > 3 秒）、磁盘 / 内存 / 存储水位、数据库连接数等。另配每日成本预算双档告警，异常支出当天可见。

9已识别风险与整改建议

以下事项均为迁移期已知的临时性安排，已纳入管控清单，按建议优先级列出：

级别事项现状与影响整改建议
HIGH 文件直链公开可读 为兼容旧版文件链接，全部存储桶临时开放了对象公开读取；知悉链接者无需登录即可访问文件 应用改造为预签名 URL（带时效的临时链接）后关闭公开读取
HIGH Kafka 控制台公网可达 用于查看验证码消息的 Kafka 控制台（kafka-ui，含生产）当前对公网开放，仅靠登录口令防护；生产侧涉及真实数据 收敛为 IP 白名单或 VPN 接入；作为最高优先级安全项处理
MEDIUM 跨域策略全开 存储桶 CORS 允许任意来源（迁移期联调便利） 收敛为实际业务域名清单
