# 优化台账

记录「发现的问题 → 处理方案 → 完成验收」的全过程。一个问题一篇文档，文档写清楚**现在是什么问题、怎么处理、怎样算完成**。

## 目录结构

| 路径 | 说明 |
|------|------|
| [待优化.md](待优化.md) | 待优化索引：编号 / 标题 / 优先级 / 摘要 / 文档链接 |
| [已优化.md](已优化.md) | 已优化索引：编号 / 标题 / 完成日期 / 摘要 / 文档链接 |
| [待优化/](待优化/) | 每个待处理问题一篇「问题 + 方案」文档 |
| [已优化/](已优化/) | 完成并通过验收的文档（从 `待优化/` 整篇移入，文件名不变，补「三、处理记录」） |

## 流转规则

1. **发现问题** → 在 `待优化/` 新建 `NNN-<领域>-<主题>.md`（编号全台账唯一、递增，三位数字），并在 [待优化.md](待优化.md) 加一行。
2. **处理中** → 文档留在 `待优化/`，在「三、处理记录」追加带日期的进展。
3. **完成** → 文档「二、6. 验收标准」全部通过后，`git mv` 到 `已优化/`，状态改为「已优化」，补「三、处理记录」（完成日期、PR/提交、alembic revision、验收结果），并把索引行从 [待优化.md](待优化.md) 移到 [已优化.md](已优化.md)。
4. **回归** → 已优化项验收不再通过时，移回 `待优化/` 并写明原因。

## 文档模板

```markdown
# <编号> <标题>

| 项 | 内容 |
|----|------|
| 状态 | 待优化 / 已优化 |
| 优先级 | P0/P1/P2（一句理由） |
| 涉及表.字段 | `表.列`, ... |
| 影响行数 | ... |
| 数据来源 | ... |
| 代码基线 | ... |
| 发现日期 | YYYY-MM-DD |

## 一、现在是什么问题
### 1. 表结构现状
### 2. 数据现状
### 3. 代码现状
### 4. 影响与风险

## 二、怎么处理（方案）
### 1. 目标表结构
### 2. 数据迁移
### 3. 后端改动
### 4. 前端改动
### 5. 环境与发布注意
### 6. 验收标准

## 三、处理记录
```

优先级：**P0** 登录 / 短信 / 身份唯一性相关；**P1** 对外展示与联系的业务主数据、会转成用户的数据；**P2** 快照 / 低频 / 已废弃 / 非结构化数据。
