## 一、现在是什么问题

### 1. 表结构现状

| 表 | 列 | 类型 | 可空 | 长度 | 是否有对应国家列 |
|----|----|------|------|------|------------------|
| quotation | from_phone | character varying | YES | 64 | 否（无 `from_phone_country_code`） |
| quotation | ship_to_phone | character varying | YES | 64 | 否（无 `ship_to_phone_country_code`） |

### 4. 影响与风险

1. **供应方国家码被写入逻辑主动丢掉**：`from_phone` 104/104 行没有国家码，其中非美国门店 29 行（UA 20、RU 9）只剩本国格式加国内前缀。这 95 张没有 From 联系人的报价单，PDF/DOCX 上印的供应方电话都没有国家码，海外客户无法直接拨打。
2. **按美国号兜底解析，结果不对**：后端 R1 和前端 F2/F3 在没有国家码时都默认 US。UA/RU 号码会被当作美国号码处理：要么原样输出（看起来不像电话），要么生成错误的 `tel:` 链接。+1 号码本身也分不清是 US 还是 CA（本国格式完全一样）。
3. **同一列三种格式**：`ship_to_phone` 一半是 E.164（54），一半是纯数字（50）；`from_phone` 有本国格式（93）和纯数字（11）两种。预览页（F4）原样显示，同一份报价单上的两个电话格式不一致。
4. **快照和来源脱节后无法恢复**：现在只能通过 `from_store_id` / `vendor_client_id` 反查国家（103/104、50/50 可以反查）。三个外键都是 `ON DELETE SET NULL`，来源一删，国家信息就永久丢失；源号码改了之后，快照和来源也会不一致（已有 1 行）。
5. **问题继续扩散**：W8（复制报价单）、W9/W10（card contact）会把没有国家码的号码继续复制下去，009 的修复也会被反复污染。
6. **风险较低的一面**：两列都没有索引、唯一约束，也没有搜索、去重、登录、短信用途。表只有 104 行，迁移锁表和回滚的成本都很小。

## 二、怎么处理（方案）

### 1. 目标表结构

| 号码列（名称不变） | 新增国家列（S2） | 国家列类型 | 号码列取值 | 约束 |
|------|------|------|------|------|
| `quotation.from_phone` | `from_phone_country_code` | `VARCHAR(2)` NULL | 本国有效号码纯数字（去掉 +、国家码、分隔符、国内前缀 0/8） | ISO 正则、号码正则、成对 |
| `quotation.ship_to_phone` | `ship_to_phone_country_code` | `VARCHAR(2)` NULL | 同上 | 同上 |

- 两列保持快照语义：建单 / 切换来源时冻结，之后来源变化不回写，和 `from_name` / `from_address` 一致。
- 号码列保持 `VARCHAR(64)`，不缩短类型（长度由 CHECK 约束，减少 downgrade 的复杂度）。

DDL 草案（迁移最后一步执行；约束命名按 000 §二.1.3：`ck_<表>__<前缀>_cc` / `_nat` / `_pair`）：

```sql
ALTER TABLE quotation
    ADD COLUMN from_phone_country_code    VARCHAR(2),
    ADD COLUMN ship_to_phone_country_code VARCHAR(2);

COMMENT ON COLUMN quotation.from_phone_country_code    IS 'ISO 3166-1 alpha-2 of from_phone (snapshot of the From store phone)';
COMMENT ON COLUMN quotation.ship_to_phone_country_code IS 'ISO 3166-1 alpha-2 of ship_to_phone (snapshot of the client phone)';

-- (回填之后) 空串归一为 NULL（当前 0 行，保留以防 uat/prod 有）
UPDATE quotation SET from_phone    = NULL WHERE btrim(from_phone)    = '';
UPDATE quotation SET ship_to_phone = NULL WHERE btrim(ship_to_phone) = '';
```

```python
import re
import phonenumbers
from phonenumbers import NumberParseException

def _digits(s): return re.sub(r'\D', '', s or '')

def _region_of(n):
    # +1/+7/+44 共用拨号码：先按号段判定(US/CA、RU/KZ)，判不出（如脱敏后的无效号）再退到该拨号码的主国家
    r = phonenumbers.region_code_for_number(n) or phonenumbers.region_code_for_country_code(n.country_code)
    return None if r in (None, 'ZZ', '001') else r

def _split(raw, region_hint):
    """-> (iso, national, status)  status ∈ ok | invalid_split | unparseable"""
    raw = (raw or '').strip()
    try:
        n = phonenumbers.parse(raw, None if raw.startswith('+') else region_hint)
    except NumberParseException:
        return None, None, 'unparseable'
    iso = _region_of(n)
    if iso is None:
        return None, None, 'unparseable'
    national = phonenumbers.national_significant_number(n)
    return iso, national, ('ok' if phonenumbers.is_valid_number(n) else 'invalid_split')

rows = conn.execute(sa.text("""
    SELECT q.id, q.from_phone, s.phone_number AS store_phone
    FROM quotation q LEFT JOIN store s ON s.id = q.from_store_id
    WHERE q.from_phone IS NOT NULL AND btrim(q.from_phone) <> ''"""))
for r in rows:
    s_iso = s_nat = None
    if r.store_phone and r.store_phone.strip().startswith('+'):
        s_iso, s_nat, _ = _split(r.store_phone, None)
    f = _digits(r.from_phone)
    if s_nat and f.endswith(s_nat) and len(f) - len(s_nat) in (0, 1):
        iso, nat, status = s_iso, s_nat, 'from_store'           # 快照与门店一致（test 103/104）
    elif s_iso:
        iso, nat, status = _split(r.from_phone, s_iso); status += ':store_region'  # 门店改过号：按门店国家解析快照本身
    else:
        iso, nat, status = _split(r.from_phone, 'US'); status += ':default_us'  # 无门店：业务默认区域并标记
    _write_or_report('from_phone', r.id, iso, nat, status, r.from_phone)
```

3. **回填 ship_to_phone**：带 + 的按 E.164 解析；纯数字的用 vendor_client 的国家列补齐。

```python
rows = conn.execute(sa.text("""
    SELECT q.id, q.ship_to_phone, vc.phone_country_code AS vc_cc

    cc = (r.vc_cc or '').strip()
    if raw.startswith('+'):
        iso, nat, status = _split(raw, None)                              # 54 行
    elif re.fullmatch(r'[A-Z]{2}', cc):                                   # 009 已把 vc 国家列改成 ISO
        iso, nat, status = _split(raw, cc)
    elif _digits(cc):                                                     # 009 之前：vc 存的是拨号码 '+1'/'1'
```

4. **写回与清单**：`_write_or_report` 的规则如下。
   - `iso` 和 `nat` 都有值：`UPDATE quotation SET <col>=:nat, <col>_country_code=:iso WHERE id=:id`。
   - 状态是 `invalid_split`、`*:default_us` 或 `*:store_region`（门店改过号）的行：**照常写回**，同时记入清单待人工复核。
   - `unparseable`：**保留原值，国家列留 NULL**，记入清单（禁止静默丢弃）。
   - 清单只输出 `quotation.id`、列名、状态和形态（数字替换成 9），**不输出号码原值**，因为 prod 是真实数据。输出到 alembic 日志（`logger.warning`），同时汇总计数。
5. **加约束**：先执行上面 DDL 的 `NOT VALID` 部分。`unparseable` 计数为 0 时，在同一迁移里 `VALIDATE`；不为 0 时保留 NOT VALID 并打印“需人工处理 N 行后执行 VALIDATE”，由后续数据修复迁移完成 VALIDATE。

**downgrade**：对国家列非空的行执行 `<col> = '+' || country_code_for_region(iso) || <col>`（拨号码在 Python 里用 `phonenumbers.country_code_for_region` 计算），然后删除 6 个约束和 2 个国家列。注意这一步是**有损**的：`from_phone` 原来的本国展示格式（括号、空格、国内前缀）无法还原，降级后统一变成 E.164。旧版 render（R1）和前端（F2）对带 + 的值反而能正确解析，所以没有功能回退。

**dry-run 偏差**（必须在 PR 里写清楚）：

- test 和 uat 都脱敏过（手机号尾部加 1）：+1 号码的 NSN 是 11 位、UA 是 10 位、RU 是 11 位，`is_valid_number` 几乎全部为 False。所以在 test/uat 演练时，预期大部分行是 `invalid_split`（国家能正确判出，号码多 1 位），而不是 `ok`。这是数据造成的，不是迁移有问题。
- 国家判定在 test 上可以核对：`from_phone` 预期 +1 75 行（US/CA 合计）、UA 20、RU 9；`ship_to_phone` 预期 +1 77 行、UA 20。另有 7 行的 vc 国家码形态是 `+9999`，会被解析成 AM 加一个多出 1 位的号码，需要 **009 先修正 vendor_client 国家列**再回填，否则这 7 行进清单。
- 真实的有效率只能在 **prod 只读快照**上 dry-run（只跑解析统计，不写库、不输出原值）。uat 用来演练流程和耗时（数据线和 prod 同源）。

```sql
-- V1 两个国家列存在且类型正确（期望 4 行；*_country_code 为 character varying / 2）
SELECT column_name, data_type, character_maximum_length
FROM information_schema.columns
WHERE table_name = 'quotation'
  AND column_name IN ('from_phone','from_phone_country_code','ship_to_phone','ship_to_phone_country_code')
ORDER BY column_name;

-- V2 6 个 CHECK 约束存在且已 VALIDATE（期望 6 行，convalidated 全为 t）
SELECT conname, convalidated FROM pg_constraint
WHERE conrelid = 'quotation'::regclass AND contype = 'c'
  AND conname IN ('ck_quotation__from_phone_cc','ck_quotation__from_phone_nat',
                  'ck_quotation__from_phone_pair','ck_quotation__ship_to_phone_cc',
                  'ck_quotation__ship_to_phone_nat','ck_quotation__ship_to_phone_pair');

-- V3 号码列只剩纯本国号码，无 + / 分隔符 / 空串（期望 0 | 0）
SELECT count(*) FILTER (WHERE from_phone    !~ '^[0-9]{4,15}$') AS bad_from,
       count(*) FILTER (WHERE ship_to_phone !~ '^[0-9]{4,15}$') AS bad_ship_to
FROM quotation;

-- V4 号码非空行国家列 100% 合法且成对（期望 0 | 0）
SELECT count(*) FILTER (WHERE (from_phone IS NULL) <> (from_phone_country_code IS NULL)
                           OR from_phone_country_code !~ '^[A-Z]{2}$')       AS bad_from_cc,
       count(*) FILTER (WHERE (ship_to_phone IS NULL) <> (ship_to_phone_country_code IS NULL)
                           OR ship_to_phone_country_code !~ '^[A-Z]{2}$')    AS bad_ship_to_cc
FROM quotation;

-- V5 国家分布核对（test 期望：from US+CA=75、UA=20、RU=9；ship_to US+CA=77、UA=20、AM=7（009 修正后））
SELECT 'from' AS col, from_phone_country_code AS cc, count(*) FROM quotation GROUP BY 1,2
UNION ALL
SELECT 'ship_to', ship_to_phone_country_code, count(*) FROM quotation GROUP BY 1,2
ORDER BY 1,3 DESC;

-- V6 快照与来源一致性不下降（只在迁移后有意义：未优化的快照上本 SQL 实测返回 104|10、70|49，因为号码还带分隔符/+）
--    test 期望：from 一致 ≥ 103/104（迁移前用“去国家码/加国内前缀后比对数字”得到的基线 103/104）；
--    ship_to 与 vc 一致 ≥ 62/70（迁移前逐字相等基线 69/70，减去 vc 国家码异常 '+9999' 的 7 行——它们按
--    '+'||拨号码||号码 解析后本国号码多出一位，009 修正前对不上，且必须出现在迁移清单中）
SELECT count(*) AS total,
       count(*) FILTER (WHERE regexp_replace(s.phone_number,'\D','','g') LIKE '%' || q.from_phone) AS from_consistent
FROM quotation q JOIN store s ON s.id = q.from_store_id
WHERE q.from_phone IS NOT NULL;
SELECT count(*) AS total,
       count(*) FILTER (WHERE regexp_replace(vc.phone_number,'\D','','g') LIKE '%' || q.ship_to_phone) AS ship_to_consistent
FROM quotation q JOIN quotation_vendor_client vc ON vc.id = q.vendor_client_id
WHERE q.ship_to_phone IS NOT NULL;
```
