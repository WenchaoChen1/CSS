# 项目交接清单:需要客户提供什么 / 不提供怎么办

> 适用于从原开发团队接收 CSS(Chain Serve)项目。下面每一项标注:**要什么 → 为什么 → 现状 → 缺失时的兜底方案**。
> 本次交接我们就是在"大部分缺失"的前提下,用右侧兜底方案先把系统跑起来的。

---

## A. 代码与版本

**A1. 全量代码与完整 Git 历史**
- 为什么:GitHub 上只有 `main`,落后真实开发线约 2.5 个月,且分支历史与生产/快照**已分叉**。
- 现状:只有 GitHub `main`(最新迁移 `c868e4eb8b15`,2026-04)。GitLab 上 4 月后的代码/迁移未推送。
- **缺失兜底**:① 索要 GitLab 仓库(或至少 `migrations/versions/` 与变更说明)的访问;② 拿不到则用我们的双库 schema 对比(`db_compare/`)逆推差异,基于 GitHub `main` 继续维护,缺失功能按快照 schema 逐步重建。

**A2. 分支/提交规范与未合并工作**
- 为什么:提交信息绑定 YouTrack 任务号(pre-commit 钩子强制)。
- **缺失兜底**:沿用 `CSS-<id>:` 提交规范;无 YouTrack 则用占位任务号并记录映射。

---

## B. 数据库

**B1. 生产/最新数据库快照**
- 为什么:让系统带真实数据运行、做迁移与对比的基准。
- 现状:有 `postgres_backup_20260628.sql`(pg_dump 二进制格式,2026-06-28 dev 快照),但其 schema 比代码新且分叉。
- **缺失兜底**:① 用现有快照 best-effort 导入(我们已做 → `css_dev`);② 无快照则用 `alembic upgrade head` 全新建库 + 必要种子数据。

**B2. 快照与代码的对齐迁移**
- 为什么:快照领先代码,`alembic_version`(`3bdd9e1f06c8`)在代码里不存在,无法直接 upgrade/downgrade。
- **缺失兜底**:已建立"代码库 vs 快照库"对比产物(`db_compare/schema_diff.txt`、`divergence_impact.md`),按列取交集导入并记录所有分叉点;最终对齐仍需 A1 的 GitLab 迁移。

---

## C. 镜像与基础设施

**C1. 私有镜像仓库访问**
- 为什么:`docker-compose.prod.yml` 的 kafka 镜像来自 `registry.devteam.space`(私有)。
- **缺失兜底**:用公共等价镜像替代——已做:`apache/kafka`(已内置于 `deploy/docker-compose.{dev,test,prod}.yml`)。

**C2. 运行环境(服务器/编排)**
- 为什么:prod 设计在 Linux(systemd journald 日志驱动)。
- 现状:本地是 Windows + Docker Desktop(不支持 journald)。
- **缺失兜底**:`deploy/` 各环境覆盖文件已内置 json-file 日志(替代 journald)+ 暴露 5432;生产仍建议 Linux。

**C3. 托管中间件(若云上)**
- 要什么:Postgres / Redis / RabbitMQ / Kafka / 对象存储 的连接信息(若客户用云托管)。
- **缺失兜底**:全部用本机容器自托管(已做:db/redis/rabbitmq/kafka 均在 compose 内)。

---

## D. 第三方密钥与凭据(最关键)

逐项:**要什么 → 缺失兜底**

| 用途 | 变量 | 缺失兜底方案 |
|------|------|------------|
| 认证密钥 | `API_KEY` / `JWT_SECRET` / `PASSWORD_SALT` / `PASSWORD_HASH_*` | 自生成 dev 值(已做);注意改了 `PASSWORD_SALT` 后旧密码哈希失效,需用应用哈希逻辑重置账号密码(已做 6 个测试账号) |
| 对象存储 S3 | `S3_*` | 本地起 **MinIO** 替代,或填占位(文件上传功能暂不可用) |
| 短信 Twilio | `TWILIO_*` | 关确认码验证(`CONFIRMATION_CODE_VERIFICATION_ENABLED=false`)直接登录;或从 `confirmation_code` 表/Kafka 读码;真实发送才需 Twilio |
| 邮件 SMTP | `SMTP_*` | 用 **Mailhog/Mailpit** 本地收件,或留空(邮件功能禁用) |
| Eden AI(发票 OCR) | `EDEN_API_TOKEN` | 留空 → 相关功能禁用,不影响启动 |
| OpenAI(ai_assistant) | `OPENAI_API_KEY` | 不启动 ai_assistant 子服务 |
| Gemini(catalog OCR) | `CATALOG_OCR_*` | 必填项给占位值满足校验(已做);不启动 catalog_ocr 子服务 |
| 地图 | `VITE_GOOGLE_MAPS_API_KEY` | 留空 → 地址/地图相关页面降级 |

> 提示:**判断哪些密钥必填,看 `config/*.py` 的 pydantic 类(无默认值=必填),不要信 `.env.example`**(它不完整)。

## E. 环境与运行配置

**E1. 各环境(dev/test/prod)的具体配置**
- 要什么:域名、对外端口、CORS 允许源、各服务 `*_WORKERS_NUMBER`、确认码开关、日志级别、`ENV`/`DEBUG`。
- **缺失兜底**:从 `config/*.py` 反推必填项 + 合理 dev 默认(已做);三环境差异见 `deploy/README.md`。

**E2. 前后端联调约定**
- 要什么:前端 API 指向、`VITE_X_API_KEY` 与后端 `API_KEY` 一致。
- **缺失兜底**:本地用 Vite 同源代理(`vite.config.ts` 代理 /api、/ws、/notifications 到 :8080)避免跨域;两端 key 已对齐。

## F. CI/CD 与流程

**F1. 流水线配置**
- 要什么:`.gitlab-ci.yml` 引用的 CI 变量、runner、部署目标、镜像推送仓库。
- 现状:仓库有 `.gitlab-ci.yml`,但 CI 变量/runner 是 GitLab 侧配置,代码里看不到。
- **缺失兜底**:本地用 `deploy/` 脚本 + `docker compose` 手动构建/部署过渡;后续按需重建流水线(GitHub Actions 或自建)。

---

## G. 文档与账号

**G1. 测试账号 / 角色矩阵**
- 现状:客户提供了 test 环境账号(Restaurant/Vendor/Packer/Driver/...);因 salt 不同已在本地重置为 `!Kolyapass1`。
- **缺失兜底**:自行在库里重置/创建账号(已做);按角色枚举梳理权限。

**G2. 任务系统 / 既有运维文档 / 架构说明**
- 要什么:YouTrack 访问、已有部署/运维手册、外部依赖清单。
- **缺失兜底**:以代码为准反推(已产出 `CLAUDE.md`、`本地运行指南.md`、`db_compare/divergence_impact.md`)。

## 本次交接:我们实际用了哪些兜底(现状速览)
