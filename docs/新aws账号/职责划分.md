# 职责划分：Terraform 管什么、脚本管什么、什么都不管谁

> 2026-07-31 整理。回答三个问题：① 两个环境组的 AWS 资源是否都由 Terraform 创建维护？
> ② 哪些不是？③ 部署 test/uat 时哪些走 Terraform、哪些走内部脚本？
> Terraform 仓库 = 工作区 `css-terraform/`（规范见其 CLAUDE.md）；内部脚本 = 本目录 `docs/新aws账号/`。

---

## 一、总原则（一句话版）

**AWS "资源"的创建/修改/删除 → 只走 Terraform；"资源里面的东西"（数据、密码值、镜像、部署动作）→ 走脚本/CI。**

产品环境组（css-prod）与非产品环境组（css-non-prod）的基础设施**已全部由 Terraform 纳管**
（共 33 个 stack，基线 = `terraform plan` 全部 No changes），仅下文 §三 清单里的边界项除外。

## 三、不在 Terraform 里的东西（完整清单）

### A. AWS 资源，但按红线/决策刻意不纳管
| 项 | 原因 | 谁管 |
|---|---|---|
| SSM 参数的**值**（及 `/css/test/*` 两个参数整体） | 密钥值进 state = 红线 | `11-parameter-store/put-params.sh` 或控制台/CLI 直接改 |
| Secrets Manager 的 `rds!` master secret | RDS 托管资源（OwningService=rds），且含密码 | AWS 自动（**7 天轮换**）；取值 `get-secret-value` |
| IAM access key（如 css-app-dev 的） | secret 进 state = 红线 | `07-iam/create-app-s3-user.sh <env> --new-key` 带外发放 |
| EC2 key pair：`wenchao`/`css-test`/`css-uat`/`css-non-prod-gw` | 无实例引用（登录靠 authorized_keys），纳管价值≈0 | `06-ec2/create-instance-keys.sh` 等（例外：`css-prod-bastion` key pair 的公钥在 TF 里） |
| 运维中转桶 `css-dbsync-582797602427` | 归属待拍板 | 暂脚本时代遗留，仅被 05 恢复流程读 |
| IAM 人类用户（css-test/Charles/Larry/Michael + Admin 组） | 账号级人类身份，不属于基础设施代码 | 控制台手动 |
| tfstate 桶 `css-tfstate-582797602427` | 鸡生蛋 | `css-terraform/bootstrap/create-tf-backend.sh`（一次性） |
| ALB 节点 EIP ×4 | AWS 随 ALB 自动分配，随 ALB 生命周期 | 无需管（标签已按新键补齐） |

### B. 根本不是 AWS 资源（Terraform 天然管不到）
| 项 | 谁管 |
|---|---|
| **数据库内部一切**：业务库（css-`<env>`-main/-ocr）、pgvector、库账号（css_app_\*/css_dev/css_ops）、密码、对象 owner、数据、脱敏 | `05-数据同步/` 全套脚本（建库/同步/恢复/脱敏/建账号/改密/reown） |
| **镜像内容**：构建、推送、tag | GitHub Actions CI（主链路）+ `03-推送镜像/push-ecr.sh`（兜底） |
| **部署动作**：拉镜像、compose up、迁移、重启 | CI 的 SSM 部署 + `09-ssm-run-command/`（deploy-env.sh/run.sh 兜底） |
| **机器内部状态**：`/opt/css-cicd`、authorized_keys、systemd/cron 自愈（10，未安装） | 部署脚本 + `06-ec2/` 密钥脚本 + `grant-dev-ssh.sh`（开发者临时钥） |
| **GitHub 侧**：仓库、Environments、分支保护、workflow 文件 | 两代码仓库自身 + `08-github-actions推镜像/`（一次性配置，基本冗余） |
| S3 对象内容、CloudWatch 日志/告警历史、CI 生成的 RDS 快照（pre-migrate-\*） | 运行时产物，无人"管理"，按保留策略自动清理 |

## 四、部署 test / uat 的完整分工

```
┌─ Terraform 负责（一次性/低频：基础设施就绪）─────────────────────────┐
│ 机器(EC2+docker via user_data) · ALB/目标组 · SG · ECR 仓库 · IAM 角色  │
│ S3 桶 · SSM 参数壳 · 日志组/告警                                       │
└──────────────────────────────────────────────────────────────────────┘
            ▼
┌─ 内部脚本/人 负责（环境初始化，一次性）───────────────────────────────┐
│ ① 配置值：改 deploy-env/<env>/backend.env → put-params.sh <env>        │
│    （或直接在控制台/CLI 改参数值——TF 只管壳不会覆盖）                  │
│ ② 数据库：05/create-databases.sh 建库 → sync-db.sh 或 restore 灌数据    │
│    → anonymize-db.sh 脱敏（非生产必跑）→ reown-db-objects.sh 移交 owner │
│    （⚠️ 每次 restore/sync 之后都要重跑 reown）                          │
└──────────────────────────────────────────────────────────────────────┘
            ▼
┌─ CI（GitHub Actions，仓库内 cicd.yml）负责（日常，每次 push）─────────┐
│ push test/uat 分支 → lint → 构建 6+1 镜像 → OIDC 假扮 css-deploy-<env>  │
│ → 推 ECR（双 tag <env>-vN + <env>）→ migrate（uat 先打 RDS 快照）       │
│ → SSM Run Command 按 Environment=css-<env> 标签定位机器部署            │
│ EC2 端 deploy.sh：从 Parameter Store 渲染 env → ECR 登录（实例角色）    │
│ → compose pull/up → 本机冒烟                                           │
└──────────────────────────────────────────────────────────────────────┘
            ▼
┌─ 手动兜底（CI 之外随时可用）──────────────────────────────────────────┐
│ 09/deploy-env.sh <env> [core|frontend|migrate|all <tag>回滚]           │
│ 09/run.sh <env> '<任意命令>'                                           │
└──────────────────────────────────────────────────────────────────────┘
```

**判断口诀**：改的东西在 AWS 控制台里是一个"资源"（有 ARN/ID）→ 去 `css-terraform` 对应 stack；
改的是资源**里面**的内容（参数值/数据/镜像/进程）→ 走本目录脚本或 CI。

## 五、快速索引

| 我想…… | 去哪 |
|---|---|
| 改机器规格 / SG 规则 / 桶配置 / 告警阈值 | `css-terraform/<对应 stack>`（见其 `运行命令.md`） |
| 改环境变量 | `deploy-env/<env>/backend.env` → `11/put-params.sh` →（后端）重启 /（前端 VITE_\*）重构建镜像 |

| 建库/同步数据/脱敏/移交 owner | `05-数据同步/` |
| 建/改数据库账号密码 | `05/create-db-accounts.sh`（全套）、`05/change-db-password.sh`（单账号） |
| 给开发者发临时 SSH 钥（带过期） | `06/grant-dev-ssh.sh` / `revoke-dev-ssh.sh` |
| 发 S3 应用用户的 access key | `07/create-app-s3-user.sh <env> --new-key` |
| 手动推镜像（CI 之外） | `03/push-ecr.sh` |
| 查各组件用法/控制台入口 | `css-terraform/使用说明/` |
