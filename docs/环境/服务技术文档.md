# CSS 服务技术文档（前端 + 后端）

> 面向运维/接手者的服务架构速查：每个环境跑什么、彼此怎么连、镜像和配置从哪来。
> 代码仓库：`Chain-Serve-Solutions/Chain-Service-Solutions-Backend`（FastAPI/Python 3.11 + Poetry）、`Chain-Service-Solutions-Frontend`（React 19 + Vite + TS）。

## 1. 总体形态：一台应用机上的三个 compose 栈

每个环境（test/uat/prod）在一台 EC2 上跑三个**独立 compose 项目**，通过外部共享网络 `css-<env>-net` 互通，可**独立部署**：

```
frontend 栈 css-<env>-frontend          backend 栈 css-<env>-backend               infra 栈 css-<env>-infra
┌─────────────────────────┐   /api /ws  ┌──────────────────────────────────┐      ┌──────────────────┐
│ frontend                │────────────▶│ nginx :80（宿主 ${PORT:-8080}）    │      │ redis 7.2        │
│ (nginx+SPA静态, 宿主:80) │ /notifications│  ├─ app（FastAPI 主 API, gunicorn│─────▶│ rabbitmq 3       │
└─────────────────────────┘             │  │   --preload, 复用镜像×4）       │      │ kafka 3.7(KRaft) │
                                        │  ├─ messenger-app（/ws 聊天）      │      │ kafka-ui(tools)  │
                                        │  └─ notifications-app :8002       │      │ ocr-redis        │
                                        │ worker（arq 任务+cron, Redis）     │      └──────────────────┘
                                        │ sms_sender / email_sender（Kafka） │      RDS（栈外，AWS 托管）
                                        │ ai_assistant（Node, :2025）        │      css-<env>-main / css-<env>-ocr
                                        │ ocr-migrator→ocr-api :8088→worker │
                                        └──────────────────────────────────┘
```

## 2. 服务清单

### 后端栈（11 容器；ECR 仓库每环境独立：`<env>/css-backend/*`，下表省略 `<env>/` 前缀）

| 服务 | 镜像（ECR 仓库） | 作用 | 关键依赖 |
|------|------------------|------|----------|
| app | `css-backend/app` | FastAPI 主 API（`/api`，`check_api_key` 门禁） | RDS、redis、**kafka（登录硬依赖：auth DI 每请求连 kafka，掉了登录 500）** |
| messenger-app | 复用 `app` 镜像 | 聊天 websocket（`/ws`） | 同上 |
| notifications-app | 复用 `app` 镜像 | 通知（`/notifications`，:8002） | RabbitMQ |
| worker | 复用 `app` 镜像 | arq 异步任务 + cron（发票 OCR 等） | redis（唯一有 healthcheck 的 app 系服务） |
| nginx | `css-backend/nginx` | 后端入口 :80，路由到 app/messenger/notifications | envsubst 三个端口变量 |
| sms_sender | `css-backend/sms-sender` | Kafka `sms_send` 消费者 → Twilio | kafka |
| email_sender | `css-backend/email-sender` | Kafka `email_send` 消费者 → SMTP（**SMTP 变量缺失会崩溃循环**） | kafka |
| ai_assistant | `css-backend/ai-assistant` | Node/Express + OpenAI（:2025 硬编码；**刻意不挂 env_file**，只注入 3 个变量） | OpenAI key |
| ocr-migrator | `css-backend/catalog-ocr` | 一次性 `alembic upgrade head`（OCR 库自动迁移） | RDS ocr 库 |
| ocr-api / ocr-worker | 复用 `catalog-ocr` 镜像 | 厂商目录 OCR（Gemini），:8088 | ocr-redis、Gemini key |

### infra 栈（自托管中间件，公共镜像不走 ECR）

redis、rabbitmq（管理插件）、kafka（KRaft 单节点，**不落盘**——未消费消息重启即丢）、kafka-ui（`tools` profile，**无认证**，仅用于非生产看 2FA 验证码 topic，须锁 IP）、ocr-redis。

### frontend 栈（1 容器）

`css-frontend/app`：多阶段构建（node:21-alpine build → nginx:alpine），SPA 静态文件 + `nginx.aws.conf` 同源反代 `/api`、`/ws`、`/notifications/` 到后端栈 nginx（无 CORS 问题）。

## 3. 数据与状态

| 存储 | 内容 |
|------|------|
| RDS `css-<env>-main` | 主库（订单/公司/用户/发票/聊天…，~130 表，alembic 管理，**主库迁移是手动/流水线独立 job**；过渡期旧实例上叫 `css_<env>`） |
| RDS `css-<env>-ocr` | OCR 微服务库（pgvector，ocr-migrator 自动迁移；过渡期旧名 `ocr_<env>`） |
| S3 桶（每环境独立） | 发票/文件（代码要求**显式 AK/SK**，走各环境专属 IAM 用户，见凭证隔离） |
| redis | 缓存 + arq 队列；rabbitmq：通知；kafka：2FA 短信/邮件事件 |

## 4. 配置注入模型（关键）

| 层 | 文件/来源 | 生效时机 |
|----|-----------|----------|
| 后端运行时 | `/css/<env>/backend.env`（Parameter Store）→ EC2 渲染 `/opt/css-cicd/env/<env>/backend.env` → compose `env_file` | **重启容器即生效**，不用重构建 |
| 前端构建期 | `/css/<env>/frontend.env` → CI 生成 `.env.<env>` → Vite 烤进静态 JS | **必须重构建镜像**才生效 |
| 强耦合键 | `API_KEY == VITE_X_API_KEY`；`CATALOG_OCR_API_KEY == OCR_API_KEY` | CI 一致性校验兜底 |

必填变量以 `config/*.py` 的 pydantic 类为准（历史教训：`.env.example` 缺 `CATALOG_OCR_*` 导致全部入口起不来）。

## 5. 已知运行特性 / 坑

- app 用 gunicorn `--preload --timeout 120`：2 vCPU 机器上多 worker 冷启动曾致 CPU 崩溃循环；
- 跨栈无 `depends_on`，靠 `restart: always` 收敛——首次全量 up 顺序必须 infra → backend → frontend；
- `PASSWORD_SALT` 决定所有存量密码有效性，环境间不可互换、迁移须原样搬运；
- 前端 `VITE_WS_BASE_URL` 烤死在镜像里——非生产指向网关机 EIP、prod 指向 ALB 域名，避免烤服务器 IP；
- 前端现存 16 个 tsc 类型错误 → 构建走 `Dockerfile.novalidate`（`npx vite build` 跳过 tsc），修完后应恢复 `npm run build`；
- 2FA 验证码在 kafka `sms_send` topic：非生产经 kafka-ui（SSH 隧道 :8085）查看。
