# 本地连接数据库（RDS css-non-prod）

> 回答的问题：**"我本地是否可以连接这个数据库？通过堡垒机去过桥连接，还是有别的方式？"**
> 结论：**可以连，但必须"过桥"**——RDS 在私有子网、没有公网地址，本机连它只有下面三条路（§2）。最后更新 2026-07-31。

## 0. 连接对象速查

| 项 | 值 |
|----|-----|
| RDS 实例 | `css-non-prod`（PG **16.14**，db.t4g.micro，us-east-1，删除保护开） |
| Endpoint | `css-non-prod.cw9qimi6uo6c.us-east-1.rds.amazonaws.com:5432` |
| 库 | test：`css-test-main`（业务主库，146 表，已脱敏）、`css-test-ocr`（pgvector）；uat：`css-uat-main` / `css-uat-ocr` ✅ 已建（数据=test 副本） |
| 用户 | 本地日常用 **`css_dev`**（密码固定；可建新库 + test/uat 四库读写）；master `postgres` **仅运维用**；应用用 `css_app_test` / `css_app_uat` |
| 密码 | 一律见工作区根 `运维访问速查.local.md`；master 由 Secrets Manager 托管、**7 天自动轮换**（取法见 §5），其余账号密码固定不轮换 |
| 堡垒机（过桥点） | `css-non-prod-bastion`（原 `css-non-prod-gw`，2026-07-30 改名）：`i-08b0ef319d08eae38`，公网 EIP `3.225.148.166`，登录用户 `ec2-user`，专属密钥文件名沿用 `~/.ssh/css-non-prod-gw.pem`（ed25519，无 passphrase） |

## 1. 为什么不能从本机直连

两道锁，缺一不可，本机都不满足：

| 锁 | 现状 | 结果 |
|----|------|------|
| 网络可达性 | RDS 建在 css-non-prod VPC 的**私有子网**，`--no-publicly-accessible`，没有公网 IP | endpoint 从公网解析出来的是 `10.20.x.x` 私网地址，本机路由根本到不了 |
| 安全组 | `css-non-prod-rds-sg` 的 5432 **只放行来自各环境 app-sg（`css-test-app-sg`/`css-uat-app-sg`）与堡垒机 `css-non-prod-bastion-sg` 的流量**（按安全组引用，不是按 IP） | 即使网络可达，你的本机 IP 也不在放行名单里 |

**为什么不应该把 RDS 改成 publicly-accessible**：
- 违反本项目网络三条铁律第 ③ 条（RDS 只能内网访问，见 [README.md](README.md)）；
- 公网可达 + 密码认证的 PostgreSQL 是自动化扫描/爆破的头号目标，等于把整库业务数据挂在公网上；
- 隧道方案（§2）零成本、5 秒建好，没有任何理由为图省事开公网。

## 2. 三种方式对比（选一条路）

| | 方式一：SSH 端口转发（**推荐**） | 方式二：SSM Session Manager 端口转发 | 方式三：上应用机用 docker psql |
|---|---|---|---|
| 一句话 | 经堡垒机把 RDS 的 5432 映射到本机 5433 | 经 SSM 做同样的端口映射，不走 22 | 不建隧道，直接在应用机上执行 SQL |
| 前提 | 本机 IP 在管理白名单（`221.214.0.190/32`）+ 密钥 `~/.ssh/css-non-prod-gw.pem` | aws cli 已配凭证 + **session-manager-plugin**（本机当前**未装**） | aws cli 已配凭证 |
| 优点 | 最简单通用，任何图形客户端都能用 | 不开 22、不需要 SSH 密钥、CloudTrail 全程审计 | 无需本地隧道，一条命令出结果 |
| 缺点 | 隧道窗口要一直开着；换网络（IP 变了）要改安全组 | 要先装插件 | 只有命令行，不适合交互式浏览 |
| 适用场景 | 日常开发：DBeaver/Navicat/psql 查数据 | 密钥不在手边、或不想放行 22 的机器 | 一次性查询、巡检、跑修复 SQL |

三种方式殊途同归：**流量都从 VPC 内部进入 RDS**（堡垒机在 `css-non-prod-bastion-sg`、应用机在各自的 `css-<env>-app-sg`，都在放行名单里），不改动任何安全边界。

## 3. 方式一：SSH 端口转发（推荐）

### 3.1 建隧道

```bash
ssh -i ~/.ssh/css-non-prod-gw.pem -N \
  -L 5433:css-non-prod.cw9qimi6uo6c.us-east-1.rds.amazonaws.com:5432 \
  ec2-user@3.225.148.166
```

- `-N`：不执行远程命令，纯转发；`-L 5433:...:5432`：本机 `localhost:5433` ↔ RDS `5432`。
- **保持这个窗口开着**，隧道随窗口关闭而断。建议加保活参数防掉线：`-o ServerAliveInterval=30 -o ServerAliveCountMax=3`。

### 3.2 配好 `~/.ssh/config` 后的简化命令

在 `~/.ssh/config` 加：

```
Host css-gw
    HostName 3.225.148.166
    User ec2-user
    IdentityFile ~/.ssh/css-non-prod-gw.pem
    ServerAliveInterval 30
```

以后建隧道只需：

```bash
ssh -N -L 5433:css-non-prod.cw9qimi6uo6c.us-east-1.rds.amazonaws.com:5432 css-gw
```

### 3.3 验证

```bash
psql -h localhost -p 5433 -U css_dev -d css-test-main -c "select version();"
```

## 4. 图形化客户端（DBeaver / Navicat / pgAdmin）

隧道开着的前提下，连接参数一律这样填：

| 参数 | 填什么 |
|------|--------|
| 主机 Host | `localhost` |
| 端口 Port | `5433` |
| 数据库 Database | `css-test-main`（看 OCR 库填 `css-test-ocr`；uat 换 `css-uat-*`） |
| 用户 Username | `css_dev`（推荐，四库读写；运维需要 master 时才用 `postgres`） |
| 密码 Password | 见 §5（`运维访问速查.local.md`；master 走 Secrets Manager） |
| SSL | 可不启用（流量已在 SSH 隧道内加密） |

**省掉手动开隧道**：DBeaver / Navicat / pgAdmin 都内置 SSH 隧道功能，在连接设置的 **SSH 页签**里填——主机 `3.225.148.166`、端口 `22`、用户 `ec2-user`、认证方式选密钥、私钥 `~/.ssh/css-non-prod-gw.pem`（无 passphrase）；主页签的 Host/Port 则直接填 RDS endpoint 和 `5432`。客户端会自己建隧道，不用再开 ssh 窗口。

## 5. 密码从哪来（分两类账号，别再拿 master 当日常账号）

| 账号 | 轮换 | 密码在哪 |
|------|------|----------|
| `css_dev` / `css_app_test` / `css_app_uat` / `css_ops` | **固定不轮换**（2026-07-30 决策）；改密走 `docs/环境运维执行脚本/05-数据库运维/change-db-password.sh` | 工作区根 `运维访问速查.local.md`（gitignore；应用账号同时在 `deploy-env/<env>/backend.env` 底稿与 SSM 参数里） |
| master `postgres`（仅运维） | Secrets Manager 托管，**每 7 天自动轮换**（`rds!` 前缀 secret；此前文档误写 90 天） | 用下面命令现取现用 |

```bash
aws secretsmanager get-secret-value --region us-east-1 \
  --secret-id $(aws rds describe-db-instances --region us-east-1 \
    --db-instance-identifier css-non-prod \
    --query 'DBInstances[0].MasterUserSecret.SecretArn' --output text) \
  --query SecretString --output text
```

⚠️ 应用已于 2026-07-30 从 master 切到 `css_app_<env>`，master 轮换**不再影响线上应用**——
它只意味着：你本地存的 `postgres` 旧密码最多 7 天就失效，要用时重跑上面的命令现取。
改了应用账号密码才需要走配置链路：`change-db-password.sh` → `put-params.sh <env>` → `deploy-env.sh <env> core`。

## 6. 方式二：SSM Session Manager 端口转发（免密钥）

```bash
aws ssm start-session --target i-08b0ef319d08eae38 \
  --document-name AWS-StartPortForwardingSessionToRemoteHost \
  --parameters '{"host":["css-non-prod.cw9qimi6uo6c.us-east-1.rds.amazonaws.com"],"portNumber":["5432"],"localPortNumber":["5433"]}'
```

之后客户端同样连 `localhost:5433`（§4 参数完全一致）。

| 优点 | 缺点 / 注意 |
|------|-------------|
| 不需要 22 端口放行、不需要 SSH 密钥 | 本机必须装 **session-manager-plugin**（当前**未装**：`winget install Amazon.SessionManagerPlugin` 或官网 msi） |
| CloudTrail / SSM 有完整会话审计日志 | Windows PowerShell 下 `--parameters` 的 JSON 引号容易被吃掉，建议在 **Git Bash** 里执行上面的命令 |
| 换网络（IP 变了）也不用改安全组 | 会话有空闲超时，断了重跑即可 |

## 7. 方式三：上应用机用 docker psql（一次性查询）

不建隧道，借 `09-远程执行与手动部署/run.sh` 在 test 应用机上跑一条 SQL（应用机在 `css-test-app-sg`，天然可达 RDS）：

```bash
bash docs/环境运维执行脚本/09-远程执行与手动部署/run.sh test \
  'docker run --rm -e PGPASSWORD=<密码> postgres:16 \
   psql -h css-non-prod.cw9qimi6uo6c.us-east-1.rds.amazonaws.com \
   -U css_dev -d css-test-main -c "select count(*) from company;"'
```

用 `postgres:16` 镜像是刻意的——客户端与服务端（PG16.14）同大版本，避免版本告警（见 §8）。适合巡检、跑修复 SQL；交互式浏览数据请用方式一/二。

## 8. 常见问题排查

| 症状 | 原因 | 处理 |
|------|------|------|
| 客户端报 `connection refused`（localhost:5433） | 隧道没开 / ssh 窗口被关了 | 重建隧道（§3.1）；加 `ServerAliveInterval` 防掉线 |
| 之前能连，现在 `password authentication failed` | 用的是 master？它每 **7 天**自动轮换 | 重跑 §5 的 Secrets Manager 命令取新密码；`css_dev` 等账号密码固定，多半是记错了（对 `运维访问速查.local.md`） |
| `database "css_test" does not exist` | 库名记错 | 库名是 **`css-test-main`**（连字符 + `-main` 后缀），不是 `css_test`，也不是 `css-test` |
| ssh 报 `Permission denied (publickey)` | 密钥用错 | 堡垒机专属钥是 `~/.ssh/css-non-prod-gw.pem`；备用通道是个人钥 `~/.ssh/wenchao`（RSA，带 passphrase，口令见本地私有记录 `运维访问速查.local.md`） |
| ssh 直接超时（连 22 都到不了） | 本机出口 IP 不是管理白名单 `221.214.0.190/32` | 换了网络就要改 `css-non-prod-bastion-sg` 的 22 放行 IP——走 css-terraform `css-non-prod/network`（管理 IP 变量）apply；或改用方式二（SSM 不受 IP 白名单限制） |
| psql/pg_dump 警告版本不匹配、dump 报错 | 本机客户端大版本低于服务端 PG16 | 升级本地客户端到 16+，或直接用 `docker run --rm postgres:16 psql/pg_dump ...`（方式三同款） |
| 连上了但表是空的 / 数据"不对" | 连成 `css-test-ocr` 或别的库了；或忘了 test 数据**已脱敏**（email 前缀 `1`、phone 后缀 `1`、口令统一 `Test1234!`） | 确认库名；脱敏是刻意为之，不是数据坏了 |
