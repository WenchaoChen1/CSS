# 职责划分：本目录脚本管什么、不管什么

> 2026-07-31 拆分：本文**只讲 `docs/环境运维执行脚本/` 脚本（+CI）的职责**。
> **Terraform 管什么/刻意不管什么 = `css-terraform/CLAUDE.md` §一（唯一出处，本文不重复）**；
> TF 之外的手动命令记录 = `css-terraform/执行手册.md` §九；`enable_prod_compute` 门控 = 其 CLAUDE.md §十二。

## 一、总原则（一句话版）

**AWS "资源"的创建/修改/删除 → 只走 Terraform；"资源里面的东西"（数据、密码值、镜像、部署动作）→ 走本目录脚本 / CI。**

**判断口诀**：改的东西在 AWS 控制台里是一个"资源"（有 ARN/ID）→ 去 `css-terraform` 对应 stack（命令见其 `运行命令.md`）；
改的是资源**里面**的内容（参数值/数据/镜像/进程/authorized_keys）→ 本目录脚本或 CI。

## 二、本目录脚本管的事（Terraform 天然管不到 或 按红线排除的）

| 领域 | 谁管 | 为什么不是 Terraform |
|---|---|---|
| **数据库内部一切**：业务库、pgvector、库账号（css_app_\*/css_dev/css_ops）、密码、对象 owner、数据、脱敏 | `05-数据库运维/` 全套 | 库内对象无 AWS ARN；⚠️ 每次 restore/sync 后必须重跑 reown |
| **SSM 参数的值**（运行时配置） | `11-parameter-store/put-params.sh`（带三方差异对比+备份+确认）或控制台直接改 | 密钥值进 state = 红线 |
| **IAM access key** | `07-获取应用iam密钥/issue-app-s3-key.sh <env> --new-key` | secret 进 state = 红线（用户/策略本体归 TF） |
| **镜像内容**：构建、推送、tag | GitHub Actions CI（主链路）+ `03-本地构建推送镜像/`（兜底） | 制品不是基础设施 |
| **部署动作**：拉镜像、compose up、迁移、重启、回滚 | CI 的 SSM 部署 + `09-远程执行与手动部署/`（兜底） | 同上 |
| **机器内部状态**：`/opt/css-cicd`、authorized_keys（一机一钥/开发者临时钥）、自愈单元（⏸ 暂不使用） | `06-服务器密钥与访问/` + `10-服务自愈与开机自启/` | 机内文件无 ARN |
| **GitHub 侧**：仓库 Variables/Environments、workflow 文件 | 两代码仓库自身 + `08-github-actions-cicd/` | 不是 AWS 资源（AWS 侧的 OIDC/角色归 TF `css-github`） |
| **账单侧操作**：成本分摊标签激活 | `12-成本账单/` | Billing 配置不是资源 |
| **TF 重建实例前的解保护** | `06/toggle-termination-protection.sh` | TF destroy 不会自动解除终止保护 |

**本目录脚本不能做的**：创建/修改/删除任何 AWS 资源（VPC/SG/EC2/ALB/RDS/桶/ECR/IAM 角色/告警…）——
这类需求一律去 css-terraform。双轨期遗留的资源创建脚本已全部删除；**两个刻意保留的例外**：① `06/create-instance-keys.sh` 创建 EC2 key pair（私钥只在创建那一刻返回一次，进 TF 违反红线 §九）；② `05/restore-dump-via-gw.sh` 首跑时自动创建一次性中转桶 `css-dbsync-*`（私有+加密，归属待拍板后再纳管）。除此之外发现还能建资源的脚本就是 bug。
（S3 对象内容、CloudWatch 日志、CI 生成的 RDS 快照等运行时产物无人"管理"，按保留策略自动清理。）

## 三、部署 test / uat 的完整分工

```
┌─ Terraform 负责（一次性/低频：基础设施就绪）─────────────────────────┐
│ 机器(EC2+docker via user_data) · ALB/目标组 · SG · ECR 仓库 · IAM 角色  │
│ S3 桶 · SSM 参数壳 · 日志组/告警                                       │
└──────────────────────────────────────────────────────────────────────┘
            ▼
┌─ 本目录脚本/人 负责（环境初始化，一次性）─────────────────────────────┐
│ ① 配置值：改 deploy-env/<env>/backend.env → 11/put-params.sh <env>     │
│ ② 数据库：05/create-databases.sh 建库 → sync-db.sh 或 restore 灌数据    │
│    → anonymize-db.sh 脱敏（非生产必跑）→ reown-db-objects.sh 移交 owner │
└──────────────────────────────────────────────────────────────────────┘
            ▼
┌─ CI（GitHub Actions，仓库内 cicd.yml）负责（日常，每次 push）─────────┐
│ push test/uat 分支 → lint → 构建镜像 → OIDC 假扮 css-deploy-<env>       │
│ → 推 ECR（双 tag <env>-vN + <env>）→ migrate（uat 先打 RDS 快照）       │
│ → SSM 按 Environment=css-<env> 标签定位机器部署                        │
│ EC2 端 deploy.sh：Parameter Store 渲染 env → pull → up → 冒烟           │
└──────────────────────────────────────────────────────────────────────┘
            ▼
┌─ 手动兜底（CI 之外随时可用）──────────────────────────────────────────┐
│ 09/deploy-env.sh <env> [core|frontend|migrate|all <tag>回滚]           │
│ 09/run.sh <env> '<任意命令>'                                           │
└──────────────────────────────────────────────────────────────────────┘
```

## 四、快速索引

| 我想…… | 去哪 |
|---|---|
| 改机器规格 / SG 规则 / 桶配置 / 告警阈值 | `css-terraform/<对应 stack>`（见其 `运行命令.md`） |
| 改环境变量 | `deploy-env/<env>/backend.env` → `11/put-params.sh` →（后端）重启 /（前端 VITE_\*）重构建镜像 |
| 部署/回滚 | push 分支走 CI；或 `09/deploy-env.sh` |
| 建库/同步数据/脱敏/移交 owner | `05-数据库运维/` |
| 建/改数据库账号密码 | `05/create-db-accounts.sh`（全套）、`05/change-db-password.sh`（单账号） |
| 给开发者发临时 SSH 钥（带过期，含续期/撤销/台账） | `06/grant-dev-ssh.sh` / `revoke-dev-ssh.sh` |
| 发 S3 应用用户的 access key | `07/issue-app-s3-key.sh <env> --new-key` |
| 手动推镜像（CI 之外） | `03/push-ecr.sh`；只构建 `03/build-images.sh` |
| 查各环境当前状态 | `css-terraform/环境实况/`（`scripts/check-live-facts.sh` 核对一致性） |
| 查各组件用法/控制台入口 | `css-terraform/使用说明/` |
| 查 Terraform 管什么/红线/决策记录 | `css-terraform/CLAUDE.md` |
