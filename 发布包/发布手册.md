# CSS 发布手册：本地推镜像到 ECR + EC2 端发布

> 生成日期：2026-07-08。适用环境：**test**（uat/prod 流程相同，换环境名与对应 `.env.<env>` 即可，prod 资源尚未创建）。
> 本文档不含任何密钥。真实凭证在：`aws-ops.local.md`（AWS 账号/命令）、`css-non-prod-key.pem`（EC2 SSH 私钥）、后端 `deploy/.env.test`（运行时配置）——均勿提交 git。
> 注意：`EC2部署清单.local.md` 记录的是旧的单文件 compose 模型，已被三栈拆分取代，只作历史参考；日常发布以**本手册**和后端 `deploy/README.md` 为准。

## 〇、发布链路总览

```
本机 Windows                          AWS us-east-1 (账号 582797602427)
┌──────────────────────┐    push     ┌─────────┐   pull    ┌──────────────────────────────┐
│ docker compose build │ ──────────► │   ECR   │ ────────► │ EC2 (100.30.61.207, /opt/css) │
│ 7 个镜像              │             │ 7 个仓库 │           │  三个 compose 栈:              │
└──────────────────────┘             └─────────┘           │  css-test-infra    (kafka 等) │
                                                           │  css-test-backend  (app 等)   │
       改了什么 → 要做什么:                                  │  css-test-frontend (SPA :80)  │
  后端代码   → 重新 build-push + deploy backend + (migrate)  └──────────┬───────────────────┘
  前端代码/VITE_* → 重新 build-push + deploy frontend                   │ 5432
  deploy/.env.test → 只需同步文件 + restart(运行时读取)        ┌─────────▼─────────┐
  deploy/*.yml / deploy.sh → 同步文件 + deploy                │ RDS css-non-prod  │
                                                             │ css_test/ocr_test │
                                                             └───────────────────┘
```

**7 个镜像**：`css-backend/{app, nginx, sms-sender, email-sender, ai-assistant, catalog-ocr}` + `css-frontend/app`。app 镜像被 4 个服务复用（app/worker/messenger/notifications），catalog-ocr 被 3 个复用（ocr-api/ocr-worker/ocr-migrator）。

**本文件夹的三个脚本**（对应三步，都可带 `-BackendRoot` 参数切换新老代码目录）：

| 脚本 | 何时用 |
|------|--------|
| `1-推送镜像到ECR.ps1` | 每次代码有改动要发布时 |
| `2-同步部署文件到EC2.ps1` | 仅当 `deploy/` 下的 compose / `.env.test` / `deploy.sh` 有改动时 |
| `3-连接EC2.ps1` | 上 EC2 执行发布命令 |

## 一、一次性前置（本机，已配好则跳过）

1. **Docker Desktop** 已安装并启动。
2. **aws cli** 已 `aws configure` 写入有 **ECR push 权限**的凭证（凭证值见 `aws-ops.local.md`）。
3. **OpenSSH 客户端**（Windows 自带 ssh/scp）；`css-non-prod-key.pem` 在 `C:\github-code\chain-serve\`（LF 换行 + 只读权限，别用会改换行符的编辑器碰它）。
4. **本机 IP 已在 EC2 安全组放行**（SSH 22 端口）。注意本机是双出口 IP（代理环境）：HTTP 走代理出口、SSH 原始 TCP 走另一出口，放行时按流量类型对应 IP（详见 `aws-ops.local.md`）。
5. **代码侧前提**：后端根下有 `deploy/`（含 `.env.test`），前端是后端的**兄弟目录**且名为 `CSS_frontend-main`，前端根下有 `.env.test`、`Dockerfile.novalidate`、`nginx.aws.conf`。
   ⚠️ v20260705 新代码要先把 `v20260705\迁移文件\` 合入两个项目（见 `v20260705\手动迁移操作文档.md`），否则脚本 1 会检查失败并提示。

## 二、第一步：本地构建并推送镜像到 ECR

```powershell
cd C:\github-code\chain-serve\发布包
.\1-推送镜像到ECR.ps1                # v20260705 新代码 → test 环境（默认）
# 老版代码: .\1-推送镜像到ECR.ps1 -BackendRoot C:\github-code\chain-serve\CSS_backend-main
# 显式 tag: .\1-推送镜像到ECR.ps1 -Tag v1.2.3
```

脚本做的事（逻辑在后端 `deploy\aws\build-push.ps1`）：ECR 登录（经 `cmd /c` 包裹，规避 PS 5.1 管道 400 问题）→ 自动创建缺失的 ECR 仓库 → `docker compose build/push` 后端 6 个镜像（`deploy/docker-compose.backend.yml`）→ build/push 前端镜像（`deploy/docker-compose.frontend.yml`，用 `Dockerfile.novalidate` 跳过 tsc，构建参数 `ENV_FILE=.env.test`、`NGINX_CONF=nginx.aws.conf`）。

**两个关键认知**：
- **前端的 `VITE_*` 是构建时烤进静态 JS 的**。改了前端 `.env.test`（如 API 地址、`VITE_X_API_KEY`）必须重新跑这一步再发前端，光 restart 无效。
- **后端代码也是烤进镜像的**（`COPY src/`）。改后端代码必须重新 build-push；只有 `deploy/.env.test` 是运行时读取、改后 restart 即生效。

首次构建很慢（weasyprint/texlive + poetry install），之后有缓存。

## 三、第二步：EC2 需要的文件（何时同步、放哪里）

EC2 上的文件树根是 **`/opt/css`**（`deploy.sh` 依赖这个相对结构），需要且只需要这 5 个文件：

```
/opt/css/
└── deploy/
    ├── docker-compose.infra.yml       ← 支撑栈: kafka / kafka-ui / redis / rabbitmq / ocr-redis
    ├── docker-compose.backend.yml     ← 后端栈: app×4 / nginx / senders / ai_assistant / OCR(无 db 容器)
    ├── docker-compose.frontend.yml    ← 前端栈: SPA + 同源反代
    ├── .env.test                      ← 运行时配置(RDS/S3/密钥等, chmod 600)
    └── aws/
        └── deploy.sh                  ← 发布脚本(LF 换行 + chmod +x)
```

> 不需要把代码仓库放上 EC2：EC2 只 pull 镜像不 build，compose 里的 build context 只在本机构建时用。

**test 环境这些文件已在位**。只有当你本地改了其中任何一个（比如 RDS 密码轮换后更新 `.env.test`、切 v20260705 时更新了 compose），才需要重新同步：

```powershell
cd C:\github-code\chain-serve\发布包
.\2-同步部署文件到EC2.ps1            # scp 5 个文件 + 自动转 LF + chmod
```

（脚本会自动处理 `deploy.sh` 的 Windows CRLF 问题——bash 脚本带 `\r` 在 Linux 上直接报错。）

## 四、第三步：EC2 上的发布操作

连接：`.\3-连接EC2.ps1`（或 AWS 控制台 → EC2 → `i-08e110b5a5425980d` → 连接 → EC2 Instance Connect，用户名 `ec2-user`）。上去之后：

```bash
cd /opt/css
```

### 日常发布（最常用）

```bash
./deploy/aws/deploy.sh test deploy backend     # 只发后端(前端/中间件不动)
./deploy/aws/deploy.sh test deploy frontend    # 只发前端
./deploy/aws/deploy.sh test deploy             # 三栈全发(infra → backend → frontend 按序)
./deploy/aws/deploy.sh test migrate            # 数据库迁移(alembic upgrade head, 打 RDS css_test)
```

`deploy` = ECR 登录 + pull + `up -d --remove-orphans`。三栈是独立 compose 项目（`css-test-{infra,backend,frontend}`），靠共享网络 `css-test-net` 互访（脚本自动创建），**发某一栈不影响其他栈**。

### 首次发布 / 完整重建

```bash
./deploy/aws/deploy.sh test deploy    # 全栈按序拉起(跨栈无 depends_on, backend 靠 restart:always 重试等 infra)
./deploy/aws/deploy.sh test migrate   # 主库迁移; ocr_test 由 backend 栈内 ocr-migrator 容器在 up 时自动跑
```

### ⚠️ migrate 前必读（尤其切 v20260705 新代码的第一次）

- **先做 RDS 快照**：
  ```bash
  aws rds create-db-snapshot --region us-east-1 \
    --db-instance-identifier css-non-prod \
    --db-snapshot-identifier css-non-prod-pre-v20260705
  ```
- 切新代码首次 migrate 会从 `c868e4eb8b15` 升 **32 个迁移**到 `3bdd9e1f06c8`，含删表操作（`drop_legacy_user_management_tables` 等），且 `transaction_per_migration=True`——中途失败**不整体回滚**。
- migrate 前可先核对当前库版本：
  ```bash
  source <(grep -E '^POSTGRES_(HOST|USER|PASSWORD)=' deploy/.env.test | sed 's/^/export /')
  PGPASSWORD="$POSTGRES_PASSWORD" docker run --rm -e PGPASSWORD postgres:15-alpine \
    psql -h "$POSTGRES_HOST" -U "$POSTGRES_USER" -d css_test -tc "SELECT version_num FROM alembic_version;"
  ```
- **前后端必须同发**：新前端调 `/manufacturers/*` 新端点，配旧后端会大面积 404；worker 与 app 必须同版本。一次发布 = 后端 + 前端 + migrate 整套。

### 运维命令

```bash
./deploy/aws/deploy.sh test ps                  # 三栈状态
./deploy/aws/deploy.sh test logs backend        # 看日志(logs 必须指定栈: infra|backend|frontend)
./deploy/aws/deploy.sh test restart [栈]        # 重启
./deploy/aws/deploy.sh test down [栈]           # 停止
./deploy/aws/deploy.sh test pytest              # 跑测试套件(仅 test 环境允许, 会写库)
```

### 验证发布成功

```bash
./deploy/aws/deploy.sh test ps                                          # 各容器 Up / healthy
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/api/docs # 期待 200
```

浏览器：前端 `http://100.30.61.207`（:80，`/api`、`/ws`、`/notifications` 由前端 nginx 同源反代）；后端 API `http://100.30.61.207:8080`；kafka-ui（2FA 看码）`http://100.30.61.207:8085` → Topics → `sms_send`。

## 六、常见故障排查

| 症状 | 原因与处理 |
|------|-----------|
| 本机 ECR 登录报 400 | PS 5.1 直接管道 `get-login-password \| docker login` 的已知坑——脚本已用 `cmd /c` 包裹，别手动绕过脚本登录 |
| 本机 docker 命令行为怪异 | `C:\WINDOWS\system32\docker` 空文件遮蔽真 docker.exe——脚本统一用 `docker.exe`，手敲命令也带 `.exe` |
| push 中途报未授权 | ECR 登录 token 只有 12 小时，重跑脚本 1 即可 |
| ai-assistant 镜像构建失败（EAI_AGAIN / canvas） | 用了未修复的 alpine 版 Dockerfile——确认已合入 `迁移文件\CSS_backend-main\ai_assistant\Dockerfile` |
| EC2 上登录接口全 500 | Kafka 是登录硬依赖（auth DI 急切连 `kafka:9092`）——查 infra 栈：`./deploy/aws/deploy.sh test ps`、`logs infra` |
| 所有账号登录失败（401） | 快照导入用户的 `password_hash` 用原团队 `PASSWORD_SALT`，与 `.env.test` 的盐不一致——沿用原盐或重置密码（见《本地运行指南.md》） |
| 前端能开但接口 401 | 前端烤入的 `VITE_X_API_KEY` ≠ 后端 `API_KEY`——改一致后**重新 build-push 前端** |
| 主应用调 OCR 全 401 | 后端 `CATALOG_OCR_API_KEY` ≠ `.env.test` 的 `OCR_API_KEY` |
| RDS 连不上 / 密码错误 | 密码 90 天自动轮换——从 Secrets Manager 取新密码，更新 `.env.test` 里 **3 处**（`POSTGRES_PASSWORD`、`OCR_DATABASE_URL`、`OCR_ALEMBIC_DATABASE_URL` 的 DSN 内嵌密码），同步文件后 restart |
| email_sender 容器崩溃循环 | 启动即校验 SMTP 配置，`SMTP_*` 为空所致——填占位值或真实值 |
| app 容器反复被 SIGKILL | 2 vCPU 上多 worker 冷启动抢 CPU 超时——backend compose 已加 `gunicorn --preload --timeout 120`，确认没被改掉 |
| deploy.sh 报 `\r: command not found` | 从 Windows 拷贝带了 CRLF——用脚本 2 同步（自动转 LF），或手动 `sed -i 's/\r$//'` |
| EC2 重启后前端连不上 WS | 前端烤入的 `VITE_WS_BASE_URL` 含 EC2 IP——已绑 Elastic IP 通常不变；若 IP 真变了要改前端 `.env.test` 并重新 build-push 前端 |

安全提醒：kafka-ui 无认证且能读到 2FA 验证码，EC2 安全组的 8085 端口**只放行办公/管理 IP**；kafka 数据不落盘，down/重建会清空未消费的验证码。

## 七、新环境（uat / prod）首次搭建要点

test 环境已就绪，本节只在搭 uat/prod 时用（详见后端 `deploy/README.md`「每环境前置」）：

1. RDS：`CREATE DATABASE css_<env>; CREATE DATABASE ocr_<env>;` 并各自 `CREATE EXTENSION IF NOT EXISTS vector;`；安全组放行 EC2 → 5432。
2. S3：建桶，IAM 用户 AK/SK 填 `S3_*`（代码要求显式密钥）。
3. EC2：装 docker + compose v2 + aws cli；实例角色给 `AmazonEC2ContainerRegistryReadOnly`；`sudo mkdir -p /opt/css/deploy/aws && sudo chown -R ec2-user:ec2-user /opt/css`。
4. 本地：`cp deploy/.env.<env>.example deploy/.env.<env>` 填真实值；前端建 `.env.<env>`（`VITE_X_API_KEY`=后端 `API_KEY`，`VITE_WS_BASE_URL`=该环境地址）。
5. 用本文件夹三个脚本带 `-EnvName <env>` 走一遍：推镜像 → 同步文件 → `deploy.sh <env> deploy` → `deploy.sh <env> migrate`。
6. ⚠️ prod：migrate 前必须人工核对目标库 `alembic_version` 与代码迁移链（原团队快照库可能与代码不同步）；kafka-ui 在 prod 默认不启，临时开用 `TOOLS=1 ./deploy/aws/deploy.sh prod deploy`。
