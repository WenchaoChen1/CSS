# **1\. 目的与范围**

本文档是 CSS 平台的验收测试计划。它列出了在所交付功能被接受之前必须通过的场景，并记录每个场景的结果。

这些场景是为业务用户而非测试人员编写的：每个场景都指明了应以何种角色登录、要执行的步骤以及预期的结果。不要求了解任何实现细节。

**范围内：**

* 两种业务类型的认证与入驻流程（onboarding）

* 管理后台：主数据库、订阅客户、公司卡片、批量操作以及公司类型规则

* 制造商名录以及两种视图下的制造商卡片

* 制造商产品目录与批量导入向导

* 报价单从创建到转换为订单的完整生命周期

* 经销商门户：订单、产品、装箱单、团队与设置

* 餐厅门户：下单、订单确认以及对经销商变更的响应

**范围外：**

* 支付处理（在平台之外结算）

* 性能、负载与安全测试

* 依赖尚未做出的决策的行为——列于第 5 节

# **2\. 如何执行这些测试**

每个场景相互独立：它说明自己的起始状态，除非步骤中另有说明，否则不依赖于先前场景的执行。

**记录结果**

| 结果 | 含义 |
| :---- | :---- |
| Pass（通过） | 系统的行为与预期结果描述完全一致 |
| Fail（失败） | 系统行为不同。提交缺陷并在结果列记录缺陷编号 |
| Blocked（受阻） | 场景无法执行——环境、数据或先前缺陷导致无法进行 |
| Not applicable（不适用） | 该功能不在本次发布范围内 |

*只有当全部预期结果均得到满足时，场景才算通过。若只满足部分，记录 Fail（失败）并说明哪一部分失败；部分通过会掩盖日后在生产环境中暴露的缺陷。*

**如何阅读覆盖（Covers）列**

每个场景以 FR-QUO-014 或 FR-ADM-072 的形式引用其所验证的需求编号。这些编号在功能需求文档中是稳定的，因此失败的场景可以追溯到确切的需求，而变更的需求也可以追溯到需要重新执行的场景。

# **3\. 测试数据与环境**

以下账号必须在测试开始前存在。若某角色尚未实现，请予以注明并将依赖它的场景标记为 Blocked（受阻）。

| 账号 | 角色 | 用途 |
| :---- | :---- | :---- |
| CSS 管理员 | 平台管理员 | 主数据库、订阅客户、公司卡片、导入 |
| 经销商 CEO | 经销商公司 CEO | 完整经销商门户访问权限、设置与权限 |
| 经销商销售员 | 销售员 | 归属单一用户的报价单；重新分配与权限检查 |
| 经销商打包员 | 打包员 | 装箱单组装 |
| 经销商司机 | 司机 | 取货、到达与交付确认 |
| 制造商用户 | 制造商 | 制造商视图下的制造商卡片、产品目录上传 |
| 餐厅业主 | 餐饮客户业主 | 下单、报价单响应、订单确认 |
| 第二经销商 | 经销商公司 CEO | 跨经销商隔离检查 |

**需要准备的数据**

* 一个至少拥有二十个目录产品的制造商，其中若干产品属于同一类目

* 一个已保存地址、联系人与信用额度的餐厅客户

* 一份 CSV 格式与一份 XLSX 格式的有效导入文件，以及一份故意构造的格式错误文件

* 一份用于主发票识别场景的发票 PDF

* 一家拥有子公司的公司，用于公司类型变更场景

* 一家订阅状态为 ACTIVE（生效）的公司和一家从未订阅过的公司

# **5\. 因待决问题而受阻的场景**

在相应决策做出之前，以下场景无法写成通过或失败的测试，因为需求目前描述了两种互不相容的行为。将它们列出，是为了在验收期间就能看到这些缺口，而不是在生产环境中才被发现。

| 领域 | 未决内容 | 对测试的影响 |
| :---- | :---- | :---- |
| 订单状态模型 | 存在两套状态集：一套包含 pending（待处理），另一套包含 On the Way（在途）和 Arrived（已到达） | 状态流转测试无法确定预期值。场景 UAT-VND-06 和 UAT-RST-15 假定采用第二套状态集 |
| 总计公式 | 所述公式遗漏了税费、GST 和信用额，而订单卡片中包含它们 | 在某个公式成为权威依据之前，无法编写任何针对订单或发票总额的算术测试 |
| 行小计 | 一处定义包含数量，另一处不含 | 同样的问题适用于所有行级检查 |
| 产品目录必填字段 | 业务规则中有四个必填字段，数据模型中有十一个，且后者不含 SKU 或计量单位（UoM） | UAT-CAT-05 和 UAT-CAT-08 假定采用数据模型。若决策不同，两者都要修改 |
| 产品唯一性键 | 是公司产品目录内的 SKU，还是客户编号加型号 | 重复检测测试取决于适用哪个键 |
| PDF 导入 | 一个来源要求将 PDF 解析进映射界面，另一个来源则取消导入并转入人工流程 | 无法编写任何 PDF 导入场景 |
| 导入中的无效行 | 阻止整个导入，还是导入有效行并报告其余行 | UAT-CAT-05 的预期结果将完全改变 |
| 订阅客户表中的 NOT SUBSCRIBED（未订阅） | 关于此类公司是否出现在该表中有三种相互矛盾的表述 | 在三种解读下，UAT-ADM-15 和 UAT-ADM-19 无法同时满足 |
| Convert to invoice（转换为发票）权限 | 该操作是仅限经理，还是由可配置的审批规则管控 | 无法确定针对销售员的权限测试的预期结果 |
| 通过批量编辑变更公司类型 | 阻塞校验是否适用于批量路径以及级联子公司 | UAT-ADM-07 和 UAT-ADM-30 在实践中可能相互矛盾 |

**严重级别**

| 级别 | 定义 |
| :---- | :---- |
| Critical（严重） | 金额计算错误、数据丢失，或某方看到了其不应看到的数据 |
| Major（主要） | 场景无法完成且不存在变通方案 |
| Minor（次要） | 场景可以完成，但行为偏离需求 |
| Cosmetic（外观） | 仅涉及措辞、对齐或格式 |

*凡涉及制造商、经销商与客户之间价格可见性的问题，无论在屏幕上表现如何，默认均为 Critical（严重）。功能需求第 1 部分中的保密规则是商业承诺，而非显示偏好。*
