## 1. preprod 容器拓扑（实测 22 个容器，均 Up 12 天）

由 3 个 docker compose 项目组成：`css-backend`、`css-frontend`、`dt-gitlab-runner`。

**核心应用（GHCR 镜像 `css-backend__app:preprod-<sha>`，一个镜像多进程）**
| 容器 | 角色 |
|------|------|
| `css-backend__app` | 主 API（gunicorn+uvicorn） |

| `css-backend__notifications-app` | 通知 ASGI（RabbitMQ） |
| `css-backend__worker` | arq 任务 worker（Redis） |
| `css-backend__nginx` | 反向代理入口 |

**中间件（全部单机容器，无托管/无备份）**
| 容器 | 镜像 | 备注 |
|------|------|------|
| `css-backend__db` | GHCR `css-backend_db`（PG） | **主数据库在容器里，非 RDS** |
| `css-backend__redis` | redis:7.2.1-alpine | 缓存/worker |
| `css-backend__rabbitmq` | rabbitmq:3-management | 通知；**guest/guest** |

**Catalog OCR 微服务（独立一套）**
| 容器 | 镜像 |
|------|------|
| `css-backend__ocr-api` / `ocr-worker` | css-backend-ocr-* |

| `css-backend__ocr-redis` | redis:7.2.1-alpine |

**队列消费者 / 其他**
| 容器 | 说明 |
|------|------|
| `css-backend__sms-sender` / `email-sender` | Kafka 消费者发短信/邮件 |
| `css-backend__ai_assistant` | Node/OpenAI，**2025 端口发布到宿主**（代码 #14，未鉴权代理） |

## 2. 运行时配置（app 容器实测 117 个环境变量）

| 变量 | preprod 值 | 问题 |
|------|-----------|------|
| `ENV` | `prod` | 名义生产 |
| **`DEBUG`** | **`1`** | 🔴 生产开调试；叠加代码 #51「debug 时返回完整堆栈」= 对客户端泄露堆栈 |
| **`SQL_ECHO`** | **`1`** | 🟠 生产打印全部 SQL，性能 + 泄露 |
| `LOG_LEVEL` | 20(INFO) | 尚可 |
| `POSTGRES_HOST` | `db`（容器） | 非托管 |
| `POSTGRES_USER` / `DB` | `postgres` / 默认库 | 🟡 用超级用户 + 默认库名 |
| `RABBITMQ_USER/PASSWORD` | `guest`/`guest` | 🟡 默认弱凭据 |

> 详细的密钥比对（preprod vs 本地 test 文件、是否复用）见 [05-环境变量与密钥审计](05-环境变量与密钥审计.md)。

## 3. 服务器层面的问题

| 级别 | 问题 |
|------|------|
| 🟠 HIGH | **数据持久化脆弱**：主库、OCR 库均为**单机容器**，无 RDS、无自动备份、无多 AZ；EBS 单盘一坏即全丢。Kafka 数据完全不落盘。 |
| 🟠 HIGH | **一台 EC2 塞下 22 个容器**（app+db+redis+rabbitmq+kafka+OCR 整套+CI runner），CPU/内存争抢、无资源隔离；任一中间件 OOM 影响全站（曾在 test 环境出现 gunicorn CPU 崩溃循环）。 |
| 🟠 HIGH | **管理界面/未鉴权端口对外暴露**：pgadmin、kafka-ui、ai_assistant(2025) 直接发布宿主端口，仅靠安全组兜底。 |
| 🟡 MEDIUM | **`gitlab-runner` 与生产负载同机**，且挂 `docker.sock` → CI 侧沦陷即接管整机。 |
| 🟡 MEDIUM | **默认/弱凭据**：postgres 超级用户、rabbitmq guest/guest。 |
| 🟡 MEDIUM | **无反向代理层的统一 TLS/WAF/限流**（无 ALB/CloudFront），全靠单台 nginx。 |
| 🟡 MEDIUM | **配置漂移**：dev/preprod 不在 Terraform 内，SG/实例手工维护，难审计。 |

## 5. 建议（服务器层）

1. **数据库上托管**：主库/OCR 库迁 RDS（或至少容器卷 + 定时快照到 S3 + 异地）。
2. **拆分职责**：中间件与 CI runner 移出应用机；至少给容器配 `mem_limit`/`cpus` 防连锁 OOM。
3. **收敛暴露面**：pgadmin/kafka-ui/ai_assistant 不对公网，走跳板或内网；补 TLS/限流。
4. **关掉生产 DEBUG/SQL_ECHO**，改强口令替换 postgres 超级用户与 rabbitmq guest。
5. 用 Terraform 纳管全部实例与安全组，消除漂移。
