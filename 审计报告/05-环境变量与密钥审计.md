## 2. 真正的大问题：不是复用，而是"生产开调试 + 弱默认凭据 + 明文真实密钥"

| 项 | preprod | test 文件 | 判定 |
|----|---------|-----------|------|
| `ENV` | prod | prod | 两个都标 prod |
| **`DEBUG`** | **1** | **1** | 🔴 生产/类生产开调试 |
| **`SQL_ECHO`** | **1** | **1** | 🟠 打印全部 SQL |
| `POSTGRES_USER` | postgres | postgres | 🟡 超级用户 |
| `POSTGRES_DB` | 默认库 | 默认库 | 🟡 用默认库名 |
| `RABBITMQ_USER/PASS` | guest/guest | guest/guest | 🟡 默认弱凭据 |

`DEBUG=1` 叠加代码审计 #51（"debug 开启时全局异常处理向客户端返回完整堆栈"）→ **生产接口报错会把堆栈/内部结构暴露给攻击者**。这是本次 env 审计最该先修的一条。

## 4. 配置错误（顺带发现）

- **S3 变量疑似写反**：`S3_STORAGE_BUCKET_NAME=eu-central-1`、`S3_LOCATION=files`、`S3_ENDPOINT_URL=https://chain-serve-test.s3.amazonaws.com`。桶名被写成了区域、location 被写成了 `files` —— 正常应是 `BUCKET_NAME=chain-serve-test`、`LOCATION=eu-central-1`。需核对代码如何消费这几个变量（可能因端点 URL 兜底才"碰巧能用"）。
- `PORT=8888`（test 文件）与实际 nginx 端口需核对一致性。
