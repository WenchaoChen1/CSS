# 07 · 前端架构现状与问题（v20260705）

> React 19 + TypeScript + Vite SPA，约 **2069 个 .ts/.tsx 文件**。

---

## 1. 现在是怎么做的

**技术栈**：
- 路由：**TanStack Router**（非 react-router）
- 服务端状态：**TanStack Query**；客户端状态：**Zustand**（userStore/modalStore/orderFlowStore…）
- 表单：react-hook-form；表格：TanStack Table；i18n：i18next
- 样式：SCSS Modules（`typed-scss-modules` 生成 `.d.ts` 类型）
- 权限：**react-abac** 的 `AccessControlProvider`（基于角色的访问控制）

**目录（FSD 式分层）**，`src/` 下：
- `ui/`：`pages → widgets → features → entities → shared` 五层；页面专属 UI 放 `pages/<Page>/ui/`，复用组件下沉 `entities/`、`shared/`。
- `api/`：按后端域一文件（orders.ts/products.ts/clients.ts…），axios 薄封装；`config/axios/` 放拦截器与刷新逻辑。
- `stores/`：Zustand。`app/`：`App.tsx`(providers + RouterProvider)、`providers/`（含 AccessControlProvider）、`constants/router`。
- 别名导入：`ui/… api/… hooks/… stores/… models/…`（不用相对 `../../`）。

**优点**：现代化、类型化、分层清晰、状态职责分离（server/client/url/form 各归其位）。

## 2. 已知技术债（仓库 `REFACTORING.md` 自述）

- 重复的向导组件（AddClients / UploadProducts / Catalog 三处雷同）。
- 重复的报表表格、重复的类型定义（应合并到 `src/models/common/entities.ts`）。

## 3. 审计发现的问题（明细见 [04](04-代码审计发现清单.md)）

### 3.1 令牌与鉴权 🟡
- **access token + 长效 refresh token 存 `localStorage`**（`config/axios/privateHttp.ts`、`utils/storageManager.ts`）→ 任意 XSS 即可窃取、完整接管账户并持久化（#30/#31/#36）。建议 refresh 用 httpOnly cookie。
- **`X-API-KEY` 被打进公开前端 bundle**（`config/axios/http.ts`、`Dockerfile`）→ 网关共享密钥可被任何人从 JS 里提取（#54/#65/fe:.gitlab-ci #19）。这类"前端持网关 key"的设计本身需重估。
- **管理员/特权路由无前端授权守卫**，是否管理员仅凭客户端解码的 JWT 判定（#59）——真正的边界必须在后端（结合后端越权问题风险叠加）。

### 3.2 缓存与数据串号 🟡
- **登出未清空 React Query 内存缓存**：同一标签页换用户登录可能读到上一个用户的数据（#32）。
- **付款 query key 漏了 order/invoice id**：不同发票的付款数据会命中缓存并预填到付款表单（#33）——潜在错误记账。

### 3.3 业务计算与后端不一致 🟡
- 订单行小计**对折扣前的毛额计税且总是向上取整**，与后端权威口径不一致 → 税额偏高（#34）。

### 3.4 安全响应头 / 其他 🟡/⚪
- 前端 nginx **缺 CSP / X-Frame-Options / nosniff** 等安全头（#37/fe:nginx.conf）。
- `getClientBillInfo` 多加一层 `/api` 前缀 → `/api/api/…` 必 404（#56）；请求拦截器登出时发 `Bearer null`（#57）；发票生成函数形参名与 URL 段矛盾（IDOR 陷阱，#58）。
- 表单校验 `mergeRules` 按函数名去重，多个匿名校验器互相覆盖（#61）；order 表格就地改 react-hook-form 的 `getValues()` 活对象（#60）。
- **God-file**：order/packing-slip 相关 hook 超 800 行、混合表格/动作/UI 关注点（#62）。

---

## 4. 建议优先级

1. **令牌存储改造**：refresh token 用 httpOnly cookie，降低 XSS 接管面。
2. 重估"前端持 `X-API-KEY`"的网关设计；至少不把它当作安全边界。
3. 登出清空 Query 缓存、修付款 query key，杜绝跨用户/跨发票数据串号。
4. 对齐前后端金额/税费计算口径（以后端为准）。
5. 补齐前端 nginx 安全响应头；按 `REFACTORING.md` 消重、拆分 god-file。
